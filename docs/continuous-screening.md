# 持续委托提示词筛选

在来源的「持续委托 → 设置」中填写「大模型筛选提示词」。定时任务每次读取来源后，先按负责人、必须包含的标签和开放状态得到候选批次，再把整批候选和提示词一起交给持续处理模型进行一次筛选。模型可结合标题、完整正文、标签、负责人、Issue 里程碑和父子 Issue 关系，对整批候选应用复杂包含、排除和比较条件。Project 来源还会按 Issue node ID 关联对应的项目字段，包括 Status、Milestone、自定义字段和字段是否截断的信息。保存设置也会运行这一步，便于查看当前筛选结果。

例如：

> 只处理需求明确、能独立完成的功能缺陷。排除纯文档、纯格式调整，以及需要先做产品决策的事项。缺少复现步骤的缺陷先排除，并说明缺少的信息。

模型为每项返回是否匹配和中文理由。Project 的 Status 表示工作流状态，与 Issue 的开放/关闭状态分别取值。仓库来源提供 Issue 的里程碑，但没有 Project Status；需要按 Project 状态筛选时请选择对应 Project 来源。旧观测缺少 milestone 表示尚未采集，`null` 表示已确认没有里程碑。项目字段截断时，模型会保留信息不完整的事实。里程碑、项目字段值和截断标记均纳入筛选变化标识，来源刷新发现变化后重新判定；模型生成期间事实变化会拒绝旧结果。

匹配项沿用队列设置的创建时间顺序与并发上限。被排除的项不再作为队列行展示，队列上方会显示本次筛选的候选、命中与排除数量；命中为 0 时直接说明可能原因，并可展开查看每项排除理由。排除结果只是当前条件下的判定，筛选提示词、范围或 Issue 内容变化后会重新判定，满足条件的项会重新回到队列。等待筛选的项显示「等待大模型筛选」，不会启动处理。筛选沿用「执行目录、模型与权限」中的持续处理模型，不创建处理会话。

提示词留空时只使用原有条件。每次定时更新、手动更新或保存设置时，都会对当次候选批次进行筛选。已经接入的处理、暂停、人工排除和验收历史保留。

「更新等待任务」会读取来源并重试失败的筛选；自动队列按更新周期读取新候选，更新周期默认 30 分钟，可按需设为 30～60 分钟或更长。模型调用失败、输出缺项、重复或范围外的 Issue 时，显示错误并保留等待状态，不把未判定项作为匹配放行。配置保存本身保留队列原来的暂停或开启状态。

整批候选使用一次模型请求，不拆成多个独立小批。模型筛选期间，已有任务的接续、暂停与恢复维护照常推进。单次模型调用超时为两分钟；模型上下文不足或响应不完整时显示错误，可缩小硬性条件范围后重试。

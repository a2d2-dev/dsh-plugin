# 持续委托提示词筛选

在来源的「持续委托 → 设置」中填写「大模型筛选提示词」，保存后会更新等待任务。负责人、必须包含的标签和开放状态仍先行生效；通过这些条件的候选再由持续处理模型读取标题、完整正文、标签、负责人和父子 Issue 关系，逐项判断是否符合提示词。

例如：

> 只处理需求明确、能独立完成的功能缺陷。排除纯文档、纯格式调整，以及需要先做产品决策的事项。缺少复现步骤的缺陷先排除，并说明缺少的信息。

模型为每项返回是否匹配和中文理由。匹配项沿用队列设置的创建时间顺序与并发上限；排除项保留在「历史」分类中，可展开「查看摘要」查看理由。等待筛选的项显示「等待大模型筛选」，不会启动处理。筛选沿用「执行目录、模型与权限」中的持续处理模型，不创建处理会话。

提示词留空时只使用原有条件。修改提示词、模型、负责人、标签或候选正文后，下次刷新重新判断受影响的待接入项；未变化的判定复用持久化结果。已经接入的处理、暂停、人工排除和验收历史保留。

「更新等待任务」会读取来源并重试失败的筛选；自动队列按更新周期读取新候选。模型调用失败、输出缺项、重复或范围外的 Issue 时，显示错误并保留等待状态，不把未判定项作为匹配放行。配置保存本身保留队列原来的暂停或开启状态。

筛选按最多 20 项分批，每批使用完整正文，序列化输入上限为 256 KiB，输出理由每项最多 2000 字符。超过输入限制会显示错误，不会截断正文后假定匹配。提示词适合逐项判断的包含和排除条件；全局排名与“只挑前几项”不属于此筛选的排序规则。

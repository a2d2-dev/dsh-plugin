# 持续委托提示词筛选

在来源的「持续委托 → 设置」中填写「大模型筛选提示词」。定时任务每次读取来源后，先按负责人、必须包含的标签和开放状态得到候选批次，再把整批候选和提示词一起交给持续处理模型进行一次筛选。模型可结合标题、完整正文、标签、负责人和父子 Issue 关系，对整批候选应用复杂包含、排除和比较条件。保存设置也会运行这一步，便于查看当前筛选结果。

例如：

> 只处理需求明确、能独立完成的功能缺陷。排除纯文档、纯格式调整，以及需要先做产品决策的事项。缺少复现步骤的缺陷先排除，并说明缺少的信息。

模型为每项返回是否匹配和中文理由。匹配项沿用队列设置的创建时间顺序与并发上限；排除项保留在「历史」分类中，可展开「查看摘要」查看理由。等待筛选的项显示「等待大模型筛选」，不会启动处理。筛选沿用「执行目录、模型与权限」中的持续处理模型，不创建处理会话。

提示词留空时只使用原有条件。每次定时更新、手动更新或保存设置时，都会对当次候选批次进行筛选。已经接入的处理、暂停、人工排除和验收历史保留。

「更新等待任务」会读取来源并重试失败的筛选；自动队列按更新周期读取新候选。模型调用失败、输出缺项、重复或范围外的 Issue 时，显示错误并保留等待状态，不把未判定项作为匹配放行。配置保存本身保留队列原来的暂停或开启状态。

整批候选使用一次模型请求，不拆成多个独立小批。模型筛选期间，已有任务的接续、暂停与恢复维护照常推进。单次模型调用超时为两分钟；模型上下文不足或响应不完整时显示错误，可缩小硬性条件范围后重试。

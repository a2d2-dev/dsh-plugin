# UI 设计规则

适用于 Harness 插件的设置页、控制面板、来源选择、列表及浮层。以下约定来自用户对实际界面的反复反馈，后续修改以此为默认；用户的新要求优先。

## 文案与信息层级

- 按钮使用当前上下文中的最短明确动作，通常为 2–4 个汉字；有实际歧义时保留对象。例如“重置”“应用”“刷新”“进入会话”。
- 标题说明当前对象或任务，例如“添加仓库”。标题下仅在用户无法判断下一步时补充一句说明。
- 同一信息在当前流程中只显示一次。账号名称放在头像菜单中，仓库名称放在来源选择器中；标题、描述和按钮不再重复它们。
- 列表计数只保留决策所需的数量；部分读取明确为“已读取”，不能当作总量。搜索范围等细节可放在对应控件的提示里。
- 浮层保留状态、可读时间和可执行动作。日期使用本地可读格式，原始时间戳留在 `dateTime` 等机器字段中。
- 账号来源与当前身份不一致、读取失败、权限限制、部分数据等会影响判断的信息必须保留。常规成功说明和内部实现术语可以省略。

| 冗长或重复的写法 | 默认呈现 |
| --- | --- |
| 重置为全部开放 Issue | 重置；提示说明重置范围 |
| 应用筛选 | 应用 |
| 刷新执行状态 | 刷新 |
| 查看 GitHub 账号 | 个人主页 |
| 来源状态 · 显示缓存 | 显示缓存 |
| 缓存 / 最后已知观察 · 目录观察时间：ISO 时间 | 一行本地日期和时间 |
| 选择当前账号可访问的仓库，添加后可浏览 Issue 和 PR | 仓库列表已表达用途时省略 |

## 控件与排版

- 刷新、关闭、添加、搜索等含义稳定的工具操作优先用现有图标，并提供 `aria-label`、悬停提示和键盘焦点。提交、授权及有风险的操作保留明确文字。
- 右上角账号入口只显示头像；下拉菜单中显示身份、状态和简短动作。
- 使用宿主的颜色、字体和交互 token。按钮高度、图标尺寸、间距与相邻控件一致，避免单独引入强调色。
- 使用对齐、间距和字重建立层级。只有需要表达独立分组时才增加外框，避免页面中再套一层大卡片。
- 列表工具栏紧凑排列搜索、筛选和数量；表格菜单内已明确列上下文时，动作写作“升序”“降序”“隐藏列”等。
- 分页列表在自身滚动区域底部自动续载，沿用列表的高度上限；加载中防止重复请求，失败后停止自动请求并保留“重试”，读完后停止续载。
- 禁用原因放在提示中，按钮名称保持稳定。重试原执行、重试接续等行为不同的操作仍需明确区分。
- 工作动态用平级切换视图，列表选项用图标弹层；常用内容直接展示，不用原生三角折叠作为主要排版方式。
- 空状态只提供一个标题、一句必要说明和一个下一步操作，收紧占高并统一对齐。无数据时不重复呈现空表头、零条计数与多段解释。

## 修改与交付检查

1. 扫描当前流程的同类按钮、菜单、标题和提示，将相同动作统一命名。
2. 对每段常驻说明判断：删除后会误解动作、数据范围或状态吗？不会则删除；仅少数场景需要则按条件显示或放入提示。
3. 检查未读取、空数据、筛选为空、读取失败和保留缓存的状态；保持状态真实，精简文案不能抹掉差别。
4. 检查深浅主题、窄宽度、长名称、焦点与图标可访问名称；留意通用元素选择器覆盖局部样式。
5. 运行受影响的交互和渲染测试及类型检查。能按项目验证地址检查渲染时再做视觉检查；无法访问时明确报告未验证，不换用未经允许的地址。

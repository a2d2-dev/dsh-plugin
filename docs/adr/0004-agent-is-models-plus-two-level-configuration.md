# Agent 由模型候选和两级配置组成，只有 CEO、工程师、评审三类

阶段要的是某种行为，而行为由模型和指令共同决定：同一个模型配上不同的指令，就是不同的工人。所以为阶段指定的单位是 Agent，不是模型。Agent 全局定义，只有三类。

## 决定

- **定义**：
  - Agent = 一个有序的 `provider/model` 候选列表 + 可选配置。
  - 全局定义，名字全局唯一。
  - 声明的候选属于 Agent；某次执行实际用了哪个模型，属于执行层的事实。
- **三类 Agent**：
  - **CEO**，也就是架构师。在主会话里和 LF 一起完成需要人参与的阶段，并推进整个任务：判断阶段切换、该换会话时换会话、派子代理、裁决。
  - **工程师**：把子任务落地成代码和 PR。
  - **评审**：审查工程师的产出。
  - QA 等更细的角色，需要时再加。
- **配置分两级**：
  - 全局配置跟着 Agent 定义走，项目配置随项目提交、只在该项目生效。
  - 两级都可以为空。
  - 项目配置不新建 Agent，也不改变 Agent 的模型。
- **配置文件的位置**：

  | Agent | 全局配置 | 项目配置 |
  |---|---|---|
  | CEO | AGENTS.md（职责）、WAKE.md（唤醒清单），随插件发布；`~/.dsh/a2d2/SOUL.md`（原则） | `<项目>/.dsh/a2d2/SOUL.md` |
  | 工程师、评审 | `~/.dsh/a2d2/agents/<Agent>.md` | `<项目>/.dsh/a2d2/agents/<Agent>.md` |

  其中 `<Agent>` 取 `engineer` 或 `reviewer`。
- **装配**：会话以某个 Agent 启动时，按下面的规则把配置合进去。
  - 两级配置都放进系统提示词：全局在前，项目在后，冲突时以项目为准。
  - 每次请求前现读文件，改动在下一次请求生效。
  - 不写进会话历史，所以压缩和交接都不会丢。
  - 模型取候选列表里第一个可用的（可用性的判定见 ADR 0009）。

## 被否方案

- **按阶段选模型、按名字给 persona，两条线并行**：「谁在做」被拆在两处。派单时临时写的提示词才是真正的角色，而这部分没人管理。
- **另设一张按角色选模型的表，与阶段表并存**：会形成两套标准。现在只有一条链：阶段 → Agent → 模型。
- **把架构师设为独立于 CEO 的第四个 Agent**：每进一个设计阶段就要换一次会话（ADR 0005），会打断连续的设计上下文。
- **由项目自定义 Agent**：同一个名字在不同项目里会代表不同的人，违背「全局身份」。
- **把身份写在首条消息里**（DSH 队友的做法）：压缩之后可能丢失，而且插件不检查它是否还在。

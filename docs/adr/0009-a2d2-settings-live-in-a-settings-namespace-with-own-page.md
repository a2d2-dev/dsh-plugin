# 阶段 Agent 表和模型候选放在插件自己的 settings 命名空间，在 A2D2 配置页编辑

阶段 Agent 表、每个 Agent 的模型候选列表、咨询的模型候选列表，都由宿主注册成带 schema 的 settings 命名空间，存在 `settings.yaml` 里，可以热加载。浏览器在 DSH 设置导航里有一页独立的「A2D2 配置页」，用来查看和编辑这些内容。

## 背景

LF 要求这些选项可以配置，并且能在界面上看到整个工作流。实测发现，模型可不可用不能只看目录：`claude-bray/claude-fable-5` 在目录里、网络也通，但连一句「reply OK」都返回 `stop_reason: refusal`；同一网关下的其他模型都正常。

## 决定

- **存什么**：
  - 阶段 Agent 表：每个阶段指定 CEO、工程师、评审三者之一（ADR 0005）。
  - 每个 Agent 的模型候选列表（ADR 0004）。
  - 咨询的模型候选列表（ADR 0008）。
  - Agent 的配置文件不放在这里（ADR 0004）。阈值、价格表等静态配置仍放在插件配置里。
- **注册与读写**：
  - 由宿主调用 `settings.register(ns, schema)` 注册。
  - DSH 的 settings RPC 只向配置客户端开放白名单内的命名空间，所以浏览器经插件自己的受信任路由读写。
- **校验**：
  - 候选列表为空，或条目不是 `provider/model` 形式时，拒绝。
  - 评审和工程师的首个可用候选相同时，只告警、不拒绝。
- **可用性分两处判定**：
  - 咨询：宿主真的发起调用，失败就按 ADR 0008 换下一个候选。
  - 派子代理、芯片新建会话：按会话模型目录，取第一个在目录里的候选。
  - 拒答只能靠手动「测试」或咨询的回落发现。
- **「测试」只在用户点击时进行**：发一次极小的调用，报告「正常 / 拒答 / 限流 / 报错」，不做后台轮询。
- **A2D2 配置页**：DSH 设置导航里独立的一页。
  - 首块画出整张公路图，每个阶段标出它的 Agent。
  - 下方编辑三个 Agent 和咨询的模型候选列表，每个候选都可以「测试」。
- **出厂默认**：

  | 对象 | 模型候选（按顺序） |
  |---|---|
  | CEO、评审、咨询 | `claude-bray/claude-fable-5-1` → `codex/gpt-6` |
  | 工程师 | `codex/gpt-5.5` → `claude-bray/claude-opus-5-5` |

  阶段 Agent 表的出厂值见 ADR 0005。

## 被否方案

- **放在静态插件配置里**：改一次就要重启宿主，而且没有界面。
- **放进插件页的一张卡片**：空间不够画整张公路图。
- **后台定时探测所有候选**：持续花钱、持续占用网关并发；而拒答多半是稳定的属性，按需测一次就够了。

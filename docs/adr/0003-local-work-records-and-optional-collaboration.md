# 本地领域记录保存已接受事实，GitHub 提供可选协同

**状态：当前目标决策。** 纯本地运行和 GitHub 协同使用同一套任务规则。已接受的业务事实由本地工作记录端口保存，GitHub 自己的状态以远端观察为准，二者通过受控发布和导入连接。

## 决定

- 本地记录完整保存 Project、Task、Project Agent、指派、目标、规格、验收、证据、父子关系和领域版本。仅保存一个 Issue URL 不能声称支持本地闭环。
- 核心命令以领域引用表达创建、指派、执行、交接与完成，不把 `gh`、Issue 编号或 GitHub Project ID 设为必要参数。
- ExternalBinding 保存领域对象到外部对象的映射、来源身份和同步观察。同一个外部对象在同一记录域中只关联一个领域对象；重复发现和导入复用原记录，不能复制正在执行的任务。
- 协同适配器发布已提交领域版本。每个外部操作有稳定身份；待发布、失败、冲突、结果未知和成功必须可区分。
- 超时导致外部创建或更新结果未知时，先核对映射、远端对象和操作结果，不能盲目重建 Issue 或重发不可安全重复的副作用。
- 外部事件只是待校验观察。校验来源、基线版本、权限、当前完成状态和执行资格后，才可成为领域变更；不使用最后写入者无条件覆盖。
- 外部负责人、标签或评论不能授予执行权。涉及正在执行的工作时，先到安全边界，再受控接纳变更。
- 完成要求必要验收与证据成立，由有权限的负责 Agent 确认；本地完成事实、执行收口、父通知和可选外部关闭具有可恢复的操作记录。
- “Task 已完成，Issue 仍 Open／关闭待同步”是合法且必须准确显示的状态。外部同步重试不重跑任务；远端重开观察不自动重新启动已验收工作。
- 若任务的验收本身要求 PR 合并、发布版本等远端动作，这些证据仍须成立。可选协同关闭 Issue 与具体任务的远端验收要求分别判断。
- 停用项目协同或解除任务关联时保留完整本地事实、映射历史、最后观察和未完成操作，不删除远端对象、不重建 Task 或释放后重复授予执行资格。

## 数据与一致性边界

工作记录存储和执行协调存储可由同一本地持久化实现承载，但须明确事务边界、版本检查和命令去重。与 DSH 日志或 GitHub 的跨系统步骤使用稳定操作身份与恢复点，不承诺全局原子提交或外部副作用恰好一次。存储技术选择由实现票据论证，不能把 GitHub 评论更新当作数据库 CAS。

## 场景

- **纯本地**：建立项目与任务 → 保存规格/验收 → 指派并显式执行 → 核验证据 → 本地完成。外部关联集合为空。
- **后来关联**：已有 Task 关联 Issue → 保存 ExternalBinding → 发布本地版本。Task、Agent、执行与历史保持不变。
- **断网完成**：先提交完成事实并收口执行 → 外部关闭失败可见 → 恢复后核对并补同步。原工作不重新启动。

## 实现覆盖

完整本地业务记录、独立 ExternalBinding 与同步队列是本次目标；现有任务绑定和部分通知仍使用 Issue 参数，需通过兼容迁移落实本决策。

# Agent 身份属于项目，职责模板与会话实例分离

**状态：当前目标决策。** 用户需要在 DSH 中持续处理工作，Agent 身份应跨会话接替保持稳定，并表达项目中的职责。CEO、工程师、评审是可复用角色模板，不是全局仅有的三位 Agent，也不是宿主会话类型。

## 决定

- Project Agent 由稳定 AgentId 与所属 ProjectId 标识，包含角色、模型候选、能力需求及项目策略。不同项目中同名 Agent 不共享业务身份。
- 全局角色模板提供可复用默认值；项目可以实例化、配置和复用 Project Agent。项目级策略覆盖模板默认值，不修改其他项目或宿主全局新会话默认值。
- CEO 是协调职责模板之一。Task 可以指派给具备协调能力的项目 Agent；不从“根会话”“主会话”或模型名称推导它必须是 CEO。
- Agent 的声明策略与执行实际采用的 provider、模型、推理强度、preset 和有效权限分别保存。更换会话不重新创建 Agent 身份，模型候选也不能代替 AgentId。
- 模型候选保存精确路由及可选推理强度。显式强度须由实际模型元数据支持，不能静默忽略或转换成未经证实的通用档位。
- 指令配置继承可复用模板和项目内容。原则与方法分开；配置引用与版本属于策略，执行装配通过 DSH 公开接口完成，不把业务身份只写在首条消息中。
- 普通 DSH 会话可保持未关联状态。接入一个工作时建立显式关联，不先要求用户手工创建 Agent 或重建已有会话；自动选用项目默认策略时须可观察。
- Agent 配置属于设置与高级能力；控制面板日常入口保持 Issue、PR、项目和关联会话。

## 后果

现有全局角色配置可作为迁移时的角色模板来源。迁移不能仅凭角色名称认定两个项目 Agent 相同，也不能在恢复旧会话时擅自覆盖用户后来修改的模型或权限。

## 实现覆盖

现有阶段 Agent 表和会话 Agent 账本可复用部分配置与绑定机制；项目级独立身份、策略覆盖及无 Issue 装配仍需实现。

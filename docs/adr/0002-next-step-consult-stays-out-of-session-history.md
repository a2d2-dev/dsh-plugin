# 下一步咨询不进入会话历史

边界卡的「下一步」入口需要模型产出候选意图。我们决定：咨询走**宿主侧一次性生成**（`ctx.llm.stream` 手构 messages，session-title-llm 同型先例），素材为会话最近消息节选 + 插件账本状态 + ask-matt 原文，结果以芯片回到边界卡；**这次生成不进入会话历史**。

## 背景

"我该干嘛"的问答不配占据之后每一轮都要携带的上下文——即使结论是"留在本会话拆票"。对话历史只属于行动本身：用户点击芯片把命令填入输入框、回车，那才是入史的时刻。

浏览器端无任何不入史的模型请求能力（apiproxy RPC 白名单为铁证），因此咨询必须经插件宿主路由面到宿主执行。模型路由跟随本会话当前路由，不新增配置键。

## 被否方案

- **入史的普通咨询轮**（对本会话 `session.command` 发一条"走五选一树"的 prompt）：实现近零且候选可追问，但每次咨询永久增重会话上下文，且候选出现在对话流而非卡片上。曾是首选，被"咨询没必要出现在历史中"的裁决否掉。
- **派 subagent 咨询**：不污染父历史但留下持久子会话，对一次轻量咨询过重。

## 后果

- 咨询免费且可反复点击，不改变会话状态；宿主生成失败时「下一步」降级为可见的错误提示，不静默。
- 候选不可追问；想深入讨论下一步时，用户随时可在对话里手动问（那是有意识选择入史）。

# 下一步咨询是宿主侧的一次性生成，不进会话历史

边界卡上的「下一步」由宿主侧一次性生成。这次生成不进会话历史，不开子会话，也不以任何 Agent 的身份运行。会话历史只属于行动本身：人点芯片、回车，那才是写进历史的时刻。

## 决定

- **形态**：
  - 宿主手工构造 messages，调用 `ctx.llm.stream`，与 session-title 的做法同型。
  - 浏览器没有不写入历史的模型调用能力，所以经由插件的宿主路由执行。
- **素材**：
  - 本会话最近消息的节选。
  - 插件记录的任务状态。
  - ask-matt 原文，按 ADR 0006 注入。
  - 不读 `a2d2-orchestrator` 技能。
- **产出**：
  - 当前位置：一句话说明，加公路图上的坐标（区 + 阶段）。
  - 阶段是否完成。
  - 下一阶段与走法，走法遵守 ADR 0005。
  - 若干候选意图，以芯片呈现。
  - 坐标必须落在公路图枚举里，否则整体拒绝，并在卡片上说明原因。
- **模型**：
  - 咨询用自己的一份有序候选列表（ADR 0009），不跟随本会话的路由。
  - 出错、拒答、限流或输出为空时，换下一个候选。
- **失败可见**：生成失败时，「下一步」显示错误提示，不静默。
- **候选不能追问**：想深入讨论下一步，就在对话里手动问，这是有意写入历史。

## 被否方案

- **作为普通的一轮写进历史**：每次咨询都会永久增加会话上下文，候选也会出现在对话流里，而不是卡片上。
- **派子代理来咨询**：会留下一条持久的子会话，对一次轻量咨询来说太重。
- **跟随本会话的路由**：某条路由可能在目录里、网络也通，却稳定地拒答（ADR 0009）。咨询需要能换到别的模型。

# 任务以 tracker 为准，插件只记主会话与交接边

每个任务都是 tracker 上的一个 issue，以 tracker 为准。插件只记 tracker 不知道的两样东西：每个任务的主会话，以及会话之间的交接边。

## 决定

- **任务树**：项目拆成任务（项目下的顶层任务叫主任务），任务再拆成子任务。每个任务都是一个 issue；to-tickets 切出的工单也是子任务，不另立概念。
- **插件的记录**：每个任务的主会话与交接边，存在项目本地的 `.dsh/a2d2` 文档里。
- **一个任务同一时刻只有一个主会话**：
  - 主会话一启动就为任务建 issue 并绑定它（`bind_main_session`）。
  - spec 写进同一个 issue。一个任务始终只有一个 issue。
- **issue 的写法**：
  - 正文顶部是「现状」（当前阶段、主会话、未定问题），CEO 随时覆盖。
  - 评论区是时间线，只记五类：
    1. 阶段切换（阶段、理由、Agent）
    2. 单向门问答
    3. 决定（只放链接）
    4. 交接（附交接文档）
    5. 子代理派发与结果（附 PR）
  - 标签标明执行方式：`a2d2:main` 是主任务，`a2d2:sub` 是以独立根会话执行的子任务，`ready-for-agent` 是由子代理执行的子任务。当前阶段和主会话只写在「现状」里，不进标签。
- **tracker 只由 CEO 用 `gh` 修改**：插件不写 tracker。哪类事件常被漏记，再考虑交给插件自动写。
- **主会话分两步换人**：
  - 准备交接时，任务标为「交接中」。
  - 后继会话 take 时，才接任主会话。
  - 接续内容里的任务状态只写指向 tracker 的指针，不写摘要。
- **子任务关闭时，插件通知父任务的主会话。** 根会话之间没有 DSH 的子代理结束通知，这一条由插件补上。

## 被否方案

- **插件自己存一份任务清单**：成了第二个 tracker，两边迟早对不上。
- **spec 单独开一个 issue**：一个任务就有了两个 issue，进展记录会分叉。

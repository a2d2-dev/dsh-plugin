# Skill 是可写真源：原文注入，永不改写

插件的两段模型指令（交接指令、下一步咨询 prompt）需要 handoff 与 ask-matt 两个 skill 的知识。我们决定：**指令 = skill 原文注入 + 纯参数信封**，插件永不把 skill 规则改写成自己的话；当 skill 与插件场景冲突时，**直接修改 skill 文件**使其对所有调用方成立，而不是在插件里包纠正层。

## 背景

两个 skill 都声明 `disable-model-invocation: true`，模型无法自行加载——这曾是旧实现把 handoff 规则复述进 `handoffInstruction` 的理由，README 也因此记下已知限制："改动 skill 不会改动这段指令，两者必须手工保持一致"。本决定消灭该限制：宿主能读文件，注入原文即引用，改写才是复制。

注入范围：SKILL.md 及其正文里相对引用的本地 markdown（如 ask-matt 的 PHASE-BOUNDARIES.md），按 skill 自己声明的资源集合走，不硬编码文件名。

信封的判据：**信封里不许出现任何 skill 已有的规则；skill 里永远不会出现文件路径、JSON 形状这类调用参数。** 例证：handoff skill 原文写死"存到 OS 临时目录"，与插件"写进交接文档两标记之间"冲突——修复发生在 skill（改为"调用方给了位置就用调用方的"，2026-09 已改），而非信封里加一句"临时目录不适用"。

## 被否方案

- **插件内嵌 skill 规则的精简版/改写版**：与真源漂移，正是被消灭的那条已知限制。
- **skill 只读、信封纠正**：纠正句本身是影子拷贝，等价于慢性漂移。

## 后果

- skill 改进（措辞、判据、边界树），插件的交接与咨询自动变好，代码零改动。
- 插件与 skill 从"只读依赖"变为"共同演进，每条知识只活在一处"。
- skill 文件缺失时不内嵌回落知识：降级必须可见（结果中标注"未读到 skill"），模型凭自身判断执行。

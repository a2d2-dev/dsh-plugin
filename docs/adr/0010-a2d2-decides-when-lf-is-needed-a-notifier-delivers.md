# A²D² 决定通知语义，可选通知服务负责送达

**状态：当前目标决策。** 等待人类、执行受阻与工作完成来自 Task 和执行事实；通知只是把这些事实送到用户已经选择的渠道。通知失败或渠道未安装不得破坏本地工作闭环。

## 决定

- A²D² 决定何时需要 LF、关联哪项工作以及应显示什么。通知以 Task 与当前有效执行为依据，不从“所有根会话都是 CEO”或某条旧会话的状态推导。
- 内容包含可理解的项目、任务标题、等待原因和有效详情／会话引用；存在启用的外部关联时可附 Issue／PR 链接，没有 Issue 也能发出完整通知。
- 通知投递经宿主可选 `notifier` 服务；A²D² 不自建另一套手机绑定和渠道配置。未安装提供者时，本地状态与站内提示仍正常。
- 通知和工作唤醒分别记录。通知送达不等于人类已回复、模型已消费或任务已完成；用户回复仍须进入对应 Task 的事件处理路径。
- 同一业务事件使用稳定身份避免重复通知。交接后事件路由到当前协调者，不能继续授权或唤醒过期主会话。
- 通用会话通知与 A²D² 业务通知应由提供者协调去重，不让每个子执行重复通知用户；提供者选择和服务注册保持明确，避免两个提供者抢占同一服务。
- 凭据与接收人配置属于通知服务的安全边界，不暴露到控制面板浏览器或模型提示。

## 实现覆盖

现有可选 notifier 接入与部分等人通知可复用。无 Issue 内容、领域事件身份与新 Task 引用须随工作记录迁移接通。渠道实现和部署属于独立组件，不是控制面板启动前置。

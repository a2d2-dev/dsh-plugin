# 芯片可以切模型、可以建空会话，但仍永不发送

扩展 ADR 0003。芯片的点击动作按候选的**走法**分派：continue 在本会话填框，必要时先把本会话切到下一站的模型；subagent 只填框、不切模型；clear 在同一工作区建一个空会话、选好模型、打开并填其输入框；compact 与 handoff 打开交接卡（focus 预填），确认后走既有一键交接序列，后继会话在 take 之前先选好下一站的模型。任何芯片点击本身都不发送消息、不发起一轮；交接卡的「确认」仍是 ADR 0003 记录的那个显式例外。

## 背景

LF 的纪律是按站用模型（想清楚用 fable、实施用 codex、评审用非实现模型），每到边界都要手动切模型、手动开会话。走法本身决定了换模型的方式：留在本会话 → 切本会话的模型；开新会话 → 创建时选好。

## 决定

- 切模型与建空会话视为「把下一步递到手边」的准备动作，不是执行：可逆（模型可再切回，空会话可弃）、不消耗 token、不进历史。发送仍是人的回车。
- 副作用必须预先可见：芯片上写「切到 fable-5-1」「新会话 · gpt-5.5」。
- 切模型走 DSH 的会话模型目录服务（与输入框旁的模型选择器共享同一状态），不自己直连 RPC；路由相同不切；站点模型表的候选都不在目录里时保持当前模型并在芯片上注明；切模型或建会话失败时退化为只填框并提示，不阻断。
- 模型路由来自站点模型表（ADR 0006），模型不选模型 id。
- compact 走「压缩并开新会话」（即一键交接序列），不填 DSH 原生 `/compact`（原地压缩）。LF 定：到边界要换模型时，新会话才能干净地在创建时选好模型。

## 被否方案

- **只填框、切模型交给人**：每个边界多两步手动操作，正是要消除的摩擦。
- **点击即切并发送**：违背 ADR 0003，生成的候选会错。
- **切模型前再弹确认**：芯片上已写明副作用，二次确认只是多一次点击。
- **compact 填原生 `/compact`**：原地压缩后仍在同一会话，与「换站换模型」的节奏不合。

# 决策归人：人点的东西只做准备，单向门交给 LF

候选由模型生成，事实和判断归模型；采纳哪个候选、什么时候执行，属于意图，归人。所以人点的芯片只做准备，不代替人执行。撤不回的决定交给 LF。

## 决定

- **芯片永不代发送**：点击只把下一步递到手边，发送永远靠人回车。
- **按走法准备**：

  | 走法 | 点击芯片做什么 |
  |---|---|
  | continue、subagent | 填本会话的输入框并聚焦 |
  | clear | 在同一工作区新建一个会话，以下一阶段的 Agent 启动，再填它的输入框 |
  | handoff、compact | 打开交接卡（focus 预填）；确认后走一键交接序列，后继会话在 take 之前以下一阶段的 Agent 启动 |

  compact 指「压缩并开新会话」，不是 DSH 原生的原地 `/compact`。
- **副作用预先写在芯片上**：例如「新会话 · 工程师」。新建会话失败时，退化为只填框，并提示原因。
- **唯一的例外是交接卡的「确认」**：这是人在卡上的显式确认，之后的 `/handoff`、新建后继、take 都只是在执行这次确认。
- **芯片只管人点的**：CEO 推进的阶段切换不经过芯片。
- **单向门与双向门**：
  - 双向门是可撤回的决定（dev 部署、实现选择），CEO 自己决定，事后同步。
  - 单向门是撤不回的决定（生产、删数据、对外发布、范围变更），CEO 用结构化提问交给 LF，并等待回答。

## 被否方案

- **点击即发送**：候选是生成出来的，会出错；一键执行错误候选的代价，远大于少按一次回车带来的好处。
- **候选只展示、不能点**：想表达意图又退回到打字。
- **执行前再弹一次确认**：芯片上已经写明副作用，二次确认只是多点一次。

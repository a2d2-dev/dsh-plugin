# 业务身份独立于平台、目录和会话

**状态：当前目标决策。** 工作应跨会话接替、来源断开和运行中断保持身份。Project、Task 与 Project Agent 属于业务层；Session、Execution、Delegation 和执行资源承载运行，不能反向定义业务身份。

## 决定

- Project、Task、Project Agent 使用平台无关的稳定 ID。项目是工作与职责的组织单位，不等于 Repository、cwd、DSH Workspace 或 GitHub Project。
- Task 保存目标、规格、验收与完成事实。现阶段每个 Task 的主存记录是一个 Issue，Issue 编号、URL 和远端节点 ID 是主存身份而不是 TaskId；纯本地主存启用前，Task 不能没有主存记录（见 ADR 0003）。
- Project 可以组织多个资源与任务；同一 Task 被多个视图收录仍是同一个 Task。在同一协调域内，执行资格按 TaskId 仲裁，不按视图、项目副本或 Issue 评论各自授予。
- 项目视图是查询规则和字段布局；“v3.0”“待处理”等视图标签不是新的 Task 身份，也不等于业务阶段。
- 工作流 Stage 表示工作进展，Generation 表示主会话的接续段次。交接或模型执行重试不自行推进业务阶段。
- 子任务是独立的 Task 与父子业务关系；子会话／委派是执行关系。一个评审会话不必对应一个新子任务，创建子任务也不必创建 DSH 子会话。
- 当前处理会话由 TaskExecution 的有效协调关联确定；历史会话、最近打开的会话、PR 评审会话都不能自动替代它。
- Session 使用宿主和会话的复合引用。Working Directory 使用宿主和规范化路径；实际目录与权限在执行时显式解析。
- DSH Goal 是会话续跑条件，不能代替 Task、验收或完成事实。

## 后果

迁移必须保存旧引用到新身份的唯一映射，并在原协调权威内处理正在执行的工作。复制记录、换 GitHub 关联或更换目录不会自动迁移执行资格。会话历史可以继续查询，业务记录不依赖旧会话一直在线。

## 实现覆盖

现有接口仍有以项目根和 Issue 编号寻址的路径；这些是待兼容迁移的实现限制，不能作为新领域定义。

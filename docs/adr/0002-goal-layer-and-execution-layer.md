# 词汇分目标层与执行层，执行层不定义目标层

用 LLM 干活时，执行是一次性的：上下文会满，会话会压缩、交接、崩溃。而「要达成什么」「交给谁做」必须挺过这些。所以词汇按寿命分两层。判据只有一句：**一样东西在交接、压缩或会话崩溃之后必须原样存在，它就属于目标层；可以丢弃、可以替换的，属于执行层。**

## 决定

- **目标层**：项目、任务、工作流、阶段、Agent。
- **执行层**：会话、主会话、子代理、交接、续跑条件。
- **会话是某个 Agent 为某个任务执行的一次运行。** 会话之间的关系（委派、交接、分叉）都属于执行层。
- **不用执行层的东西定义目标层的东西**：
  - 任务不是「会话组」。
  - Agent 不是 DSH 运行时的 `Agent` 句柄。
- **目标层的东西不寄存在执行层的记录里**：
  - 任务进展记在 tracker（ADR 0003）。
  - Agent 配置每次请求都现读（ADR 0004）。
  - 两者都不依赖会话历史。
- **DSH 的 Goal（`/goal`）属于执行层**：它是续跑条件，只管这条会话还跑不跑；任务是否完成以任务的验收为准。

## 被否方案

- **把插件的「任务」改名为「目标」**：会和 DSH 的 Goal 撞名，而 LF 的说法本来就是「项目 → 任务」。
- **沿用 DSH Agent Teams 的模型**：它把目标层的身份和任务板放进了执行层的 Lead 会话，正是这条判据要排除的做法。

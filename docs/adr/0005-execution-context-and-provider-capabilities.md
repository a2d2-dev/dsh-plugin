# 执行位置由工作要求、资源和后端能力共同决定

**状态：当前目标决策。** 项目 Agent 的职责不直接决定它必须运行在某一种会话位置。业务子任务、工作流阶段与 DSH 执行关系分开，由明确的能力需求和执行环境决定启动、委派与恢复方式。

## 决定

- 指派确定负责 Project Agent；Binding 建立业务与执行载体的关联；执行资格授予唯一有效协调权；启动调用 DSH。它们可以由一次用户意图编排，但必须保留独立事实与失败结果。
- 每次执行显式确定 runtime/host、规范化 cwd、可选 checkout、preset、模型/provider 和有效权限。Project 不等于目录；prompt 中写 `cd` 不能改变会话实际执行上下文。
- 当前处理会话承担 TaskExecution 的协调责任。评审和其他工作者可受控并行，显示为其他关联会话，不因创建时间较新而取代协调者。
- 需要人类输入、持续交互或冷恢复时，选择已证明具备对应能力的 DSH 执行路径。能力缺失时明确拒绝或保持待处理，不把角色名称当作能力证明。
- 原生 Child Session 保留宿主父子关系。CLI one-shot provider 记录为 run 与结果，不能伪称可续聊、可冷恢复的持久子会话；失败后核查副作用，再以新尝试身份重试。
- 具有独立目标与验收的工作才建子 Task；一次代码检查或评审委派可以只属于现有 Task。每项关系分别记录，不能依靠会话树推导业务任务树。
- 已有 DSH 会话可以显式关联到 Task。接管前校验项目访问、现有任务归属、实际资源与能力；保留其 Agent 身份、工作目录和有效权限，采用宿主当前有效的会话本地模型选择，不用任务启动时的模型快照覆盖它。
- 同一处理会话允许通过宿主公开接口切换 provider、模型和推理强度。模型选择是可变的执行配置，不是 Session、Project Agent 或 TaskExecution 的身份条件；模型变化本身不要求新建会话、重新接管任务或更换协调者。
- “不静默改变配置”约束插件不能擅自替用户改回旧模型，不限制用户通过宿主作出的模型选择。启动快照与当前选择不同，本身不构成 `incompatible-session`；当前模型不可用或缺少执行所需能力时，报告具体原因。
- 阶段完成以业务证据判断；执行返回、模型停止或 CLI 退出不是验收成功。更换 provider、会话段次或重试不自行改变 Stage。

## 恢复边界

受管协调会话使用可恢复的原生路径。创建和恢复经过公开 SessionController 与 preset 装配，继承实际执行环境并保存操作身份。不能只创建一个裸 Agent 对象就声称已完成工具、权限和角色装配。

## 实现覆盖

已有 native 委派、one-shot provider 和根会话装配机制。项目 Agent 引用、跨资源校验和统一能力投影需在新契约中接通，不能把既有兼容适配扩大成任意 CLI 的持久会话保证。

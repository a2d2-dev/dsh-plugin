# 芯片只填输入框，不代发送

边界卡上的候选意图芯片被点击时，把候选的命令或文本**填入 composer 并聚焦**，由用户回车执行；`kind: handoff` 的芯片改为打开交接卡并预填 focus。插件永不代替用户发送消息或发起一轮。

## 背景

UI 上的每个控件对应一个真正属于人的决策。候选由运行时模型生成（事实与判断归模型），但采纳哪个候选、何时执行是意图（决策归人）——最后一击必须留在人手里。填框而非代发也让用户可以先编辑候选文本再回车。

一个例外边界早已存在并保持不变：交接卡的「创建并交接」是用户在卡上的显式确认，其后的命令序列（/handoff、创建后继、take）是该确认的执行，不算代发。

## 被否方案

- **点击即发送**：少一次回车，但把确认从人手里拿走；候选是生成的，生成会错，错误的候选被一键执行的代价不对称。
- **候选只展示不可点**：浪费点击机会，表达意图退回打字。

## 后果

- 「继续留在本会话」类候选（kind: stay）与交接类候选获得统一的交互语义：都只是把下一步递到手边。
- 芯片文本即将进入输入框的确切内容，生成 prompt 必须约定 input 字段为可直接执行的命令或文本。

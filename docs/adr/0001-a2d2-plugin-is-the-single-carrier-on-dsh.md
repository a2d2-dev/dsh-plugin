# A²D² 插件是 A²D² 在 DSH 上的唯一载体

A²D² 的方法论词汇（CONTEXT.md、ADR）、Agent 配置、技能和 DSH 侧机制都放在这一个仓库里，一起管版本，只在 DSH 上运行。工作流是一项可以替换的方法选择，目前选定 Matt。

## 背景

LF 管理 AI 编程时有四个痛点：

1. 看不到全局：一个项目有多少任务，每个任务现在由哪条会话执行。
2. 会话上下文快满时要换会话，既要保证上下文完整，又要保证任务状态正确。
3. LF 只想提供和修订原则，需要一个 Agent 去推进工作流里的具体切换。
4. 工作流的各个阶段需要不同的能力。

原有的 `a2d2-orchestrator` 技能把方法、原则和带日期的教训混写在一份契约里，和插件各说各的。

## 决定

- **一个仓库**：词汇、Agent 配置、技能、DSH 侧机制放在一起管版本，同一项改动一次提交到位。
- **只在 DSH 上运行**：Claude Code 没有插件机制。`a2d2-orchestrator` 技能冻结、不再更新，也不另外维护一份纯文字版的 CEO。
- **工作流可以替换**：目前选定 Matt 工作流（ask-matt）。
  - 只属于 Matt 的：公路图、区、匝道、服务区、阶段边界判断树、前置条件。
  - 与工作流无关的：任务、阶段、Agent、走法。
- **不使用 DSH 实验性的 Agent Teams**：子代理由插件直接创建（ADR 0005）。

## 被否方案

- **用 Agent Teams 承载协作**：有四个问题。
  - 队友的身份和任务板都焊在队长会话上，一交接就丢。
  - 队友没法按阶段换成不同的 Agent。
  - 界面上队友和子代理是同一条会话的两个入口。
  - 任务板和 tracker 重复。
- **同时维护 DSH 版和纯文字版两份 CEO**：两份迟早会漂移。

# A²D² 依托 DSH，以单入口连接工作与会话

**状态：当前目标决策。** A²D² 的领域规则、角色模板、技能接入和宿主适配由同一插件仓库维护。DSH 继续承担会话、工具、模型、工作空间和权限执行；用户沿用原有会话与 skill，逐步启用工作管理能力。

## 决定

- 在 DSH 增加一个 A²D² 控制面板入口，保留 DSH 项目分组、会话导航及对话。面板通过宿主公开的导航与内容插槽呈现，不能另起一套会话应用或把插件页面当作独立 Vite 应用部署。
- 用户入口围绕 Issue、PR、项目；领域 Project、Task、Project Agent、执行资格在底层连接这些对象，不要求用户先操作完整领域模型才能处理工作。
- 项目选择始终指向一个具体 Project。项目页展示该项目的视图标签和内容，不提供跨全部项目的隐式执行范围。
- Issue／本地工作详情为独立页面，使用概览、会话、相关工作、活动标签；当前处理会话、接续历史、评审等关联会话分别可见。
- 领域对象与执行协调记录分域保存。现阶段任务记录由云端 GitHub 主存承载，本地工作库是缓存与执行协调状态（见 ADR 0003）；执行协调不依赖 GitHub 在线，但业务事实以主存为准。
- 现有 skill 和工作流可复用、可配置。Matt 是可选择的方法，控制面板不把公路图、阶段切换或 Agent 配置设成日常工作的必经步骤。
- 跨模型、CLI 与其他执行后端经 DSH 的公开 provider 能力接入；不使用外部进程或第三方会话系统替代宿主记录。

## 边界

领域状态归 A²D²，运行事实归 DSH。控制面板关闭不改变已授权的宿主工作；打开面板也不自动启动执行。宿主未提供的能力要显式列为依赖，不能通过私有 registry、伪造启动信息或另一个服务页面补出“已集成”的假象。

## 实现覆盖

已存在客户端插件、指示球、配置页和会话侧栏能力。完整控制面板与独立 Project 查询入口属于本次建设目标，独立 HTML 是交互证据，不是已上线功能。

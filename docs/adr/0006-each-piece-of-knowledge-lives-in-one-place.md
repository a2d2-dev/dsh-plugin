# 领域规则、方法和观察各有明确来源

**状态：当前目标决策。** 保留既有 skill 的价值，同时避免同一条规则散落在提示词、工作流图和存储中。领域正确性由明确契约保证，方法选择沿用项目配置的技能，界面组合已记录事实。

## 决定

- `CONTEXT.md` 只定义领域词汇；当前架构选择记录在 ADR；用户行为与验收写在规格；实现细节和证据留在代码、测试与能力核查中。
- 项目选择的 skill 负责开发方法，SOUL 等原则来源负责用户原则；二者不重复维护一份隐藏的工作流规则。控制面板不要求用户先学习方法论图谱。
- 提示信封传递 Task、项目策略、执行环境、已接受决定、证据与待办的可解析引用；会话中尚未落入正式业务记录的重要内容需要明确保存，不能只写空泛的“沿用之前决定”。
- 唯一身份、执行资格、版本检查、权限、验收和同步去重等领域不变量由应用与存储接口强制，不依赖模型读完 skill 后自觉遵守。
- 缺少被明确选用的方法或后端能力时，显示原因并保持可恢复状态。不能静默假装已经执行所选 skill，或通过提示词绕过权限与能力检查。
- 查询界面从工作记录、执行关联和宿主投影组合信息；阶段、已完成项、会话接续记录均依据保存的事实，不从绘图顺序或会话创建时间猜测。
- Issue／PR 是常用协同载体。工作内容可以受控发布到远端，但发布副本不取代本地已接受的领域事实。

## 后果

本仓库的 tracker 约定只约束本仓库如何安排开发工作，不构成产品运行时必须依赖 GitHub 的规则。历史评审稿和原型保留为证据时须标明其用途；当前词汇与 ADR 不同时保留相互矛盾的规范。

# A²D² 插件是方法论的载体，每个目标由一个 CEO 角色推进

插件不再只是“A²D² 在 DSH 的一个落点”，而是 A²D² 的综合载体：方法论词汇（CONTEXT.md、ADR）、CEO 角色、技能与 DSH 侧机制放在同一个仓库里一起管版本。每个目标配一个 CEO，负责推进 Matt 主干上站与站之间的切换；LF 只提供和修订原则。

## 背景

LF 管理 AI 编程时的四个痛点：

1. 看不到全局：一个目标下有多少任务，每个任务现在由哪个会话负责。
2. 会话上下文快满时要换会话，既要上下文完整，又要任务状态正确。
3. LF 只想提供和修订原则，需要一个 Agent 去推进 Matt 工作流里的具体切换。
4. Matt 工作流各步需要的智能水平不同，要按步骤选模型。

原有的 `a2d2-orchestrator` 技能把方法、LF 的原则和带日期的教训混写在一份契约里，并自带一条“派出去的一律用 Sonnet 5.5”的规定，和站点模型表（ADR 0006）各说各的。

## 决定

- **三层名字**：目标 → 任务 → 负责会话。插件原来的“任务”改名为目标；任务是目标下可独立验收的切片，与 tracker 上的工单一一对应；同一时刻一个任务只由一个负责会话负责。
- **任务清单留在 tracker**：tracker 是任务的唯一标准。目标文档只记找到这些工单的定位（label 或父工单）和每个任务的负责会话——tracker 不知道会话，这部分只能插件记。
- **CEO 推进目标**：仿照 Paperclip 的 CEO 角色（`server/src/onboarding-assets/ceo/`），每个目标一个 CEO，只做切换、派活、裁决，不做阶段内的活。grill → to-spec → to-tickets 由 CEO 开出的负责会话在同一段不断开的上下文里与 LF 完成，CEO 只判断这一段做完没有、该转到哪一站。
- **CEO 由三份文件定义**：AGENTS.md（职责）、SOUL.md（原则）、HEARTBEAT.md（每次唤醒的清单）。不设 TOOLS.md，工具清单由 DSH 提供。
- **原则在 SOUL，不在技能**：SOUL 由 LF 维护，分全局与项目两层，项目层优先。技能只放方法。
- **单向门 / 双向门**：双向门（可撤回）由 CEO 自决、事后同步；单向门（生产、删数据、对外发布、范围变更）用结构化提问交给 LF 并等待。原技能里那几段关于“不可逆怎么判”“严格程度随阶段调”的教训，压缩成这一条原则写进 SOUL。
- **按 Matt 步骤选模型**：站点模型表是唯一标准。执行者就是 implement 站，评审者就是 code-review 站；“一律 Sonnet 5.5”变成这两站的候选值。按风险分档只决定要不要派评审者，不影响选哪个模型。
- **文件位置**：AGENTS.md 与 HEARTBEAT.md 属于方法，随插件发布；全局 SOUL 在 `~/.dsh/a2d2/SOUL.md`，项目 SOUL 在 `<项目>/.dsh/a2d2/SOUL.md` 并随项目提交，项目层优先。
- **唤醒以事件为主**：负责会话做完、卡住、需要裁决时发消息叫醒 CEO，不轮询；另设低频兜底唤醒，只查疑似卡住的任务。
- **交接分两步移交负责权**：准备交接时任务标为“交接中”，后继 take 时负责会话才换成后继并通知 CEO；接续内容里的任务状态只写 tracker 指针，不写摘要。
- **只在 DSH 上跑 CEO**：Claude Code 没有插件，现有 `a2d2-orchestrator` 技能冻结、不再更新，Claude Code 继续用旧版；不维护第二份纯文字的 CEO。
- **芯片不代发送只管人点的芯片**：ADR 0003、0005 的“永不代发送”继续适用于 LF 点的芯片；CEO 推进的站间切换不经过芯片，不受这条约束。

## 被否方案

- **主会话自己按编排技能推进**：它既陪 LF 讨论又盯全局，上下文会被撑满，正好在推进者自己身上重现痛点 2。
- **插件后台按固定规则推进、不调用模型**：站间切换要判断“这一阶段做完没有”，规则写不出来。
- **CEO 自己陪 LF grill**：违背“不做阶段内的活”，且会把设计讨论塞进推进者的上下文。
- **插件自己存一份任务清单**：成了第二个 tracker，两边迟早对不上。
- **按角色选模型（执行者一个、评审者一个）**：和按站选是两套标准；角色本来就落在站上。
- **角色叫 Scrum Master**：贴合 Agile，但 Scrum Master 不派活，而 CEO 要派。叫 CEO 时不取营收/利润那层含义。

## 后果

- `a2d2-orchestrator` 技能会被拆掉：角色分工与执行契约提炼进 CEO 的 AGENTS.md 和 HEARTBEAT.md，原则进 SOUL.md，派单模板保留为 HEARTBEAT 引用的参考资料。下一步咨询里读这个技能描述、多给一颗编排芯片的逻辑（`src/consult.ts`）要跟着改。
- 代码与存储里的 Task / `.dsh/a2d2/tasks/` 要改名为目标，并迁移已有文档。
- 还没定：负责会话用哪种 DSH 会话承载、SOUL 怎么注入 CEO 会话。

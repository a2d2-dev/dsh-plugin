# #334 接续策略保存验证

## 目的

修复执行首次保存接续设置时，错误继承项目默认版本而返回 `continuation-policy-version`。显示的开关、目标 token 和预留值仍可继承项目默认，但版本归保存对象所有。保留真实并发冲突保护，允许用户明确刷新、核对后重新保存。

## 实现与自动化记录

实现提交 `d1b3d75`，基线 `e5ec679`。

1. 使用生产 WorkPanel 回调、WorkPanelController、真实 WorkApplication 和持久 DAO 构造现有历史状态：项目默认策略版本 7，当前执行无独立策略。
2. 修复前运行回归，首次保存应提交版本 1，实际提交版本 8，测试失败。
3. 修复后首次和后续保存分别提交执行版本 1/2/3，覆盖启用、关闭、300K、200K、自定义 245678 token、23456 token 预留；回读持久状态确认保存成功，项目默认不变。
4. 通过另一调用方真实保存版本 1，再提交旧表单。后端拒绝，页面提示本次未保存；刷新后显示竞争者保存的值，用户再次保存才推进到版本 2。
5. 项目默认独立从版本 7 推进到 8/9；另一项目编辑造成项目版本冲突时，同样显示可理解反馈和刷新入口，不改变执行策略。

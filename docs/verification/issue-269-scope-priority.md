# #269：业务目标、辅助证据与执行顺序

本次修复针对 [Issue #269](https://github.com/a2d2-dev/dsh-plugin/issues/269) 中可观察的执行决策，不重新执行 Global #1395。

## 原因与边界

历史规格 v4 确有六项精细验收。问题是主会话先派出精确计数、旧镜像基线审计，随后把这些发现列成实际流程的前置条件，却没有证明它们会阻止使用当前环境完成基本验证。用户明确修订后，规格 v5 已保存，当前待办仍停在旧精测计划。这是计划与持久规格不一致的直接证据。

历史公开事件的复核点：seq21 的 v4；seq1856 的派发；seq1992 的“必须先解决”；seq2019 的计数首项；seq2025/2038 的用户修订；seq2056/2057 的 v5 保存；seq2061 的停止；seq2070/2082 的最终核心标准。seq2034 是网络失败，不能作为成功流程数据。交接保存与实际接任之间存在停顿，单份旧会话日志不足以证明当前宿主调度器有同一缺陷。输入没有 Goal 来源消息，但日志存在暂停且未激活的 Goal 对象。

## 当前执行合同

托管任务启动和后继会话共同使用 `src/work-execution/continuation.ts` 的 `MANAGED_WORK_INSTRUCTIONS`。主会话先确定当前目标及真实业务依赖，再执行已授权、可行的实际步骤；辅助指标不足如实列为未验证。阻断执行需说明具体证据如何导致目标无法完成、数据受损或结果无效。

用户明确修订标准后，同步当前计划、持久规格和子代理派发口径；历史要求保留用于追溯。用户未修订的验收要求继续有效，不能以调整执行顺序为由删除。`work_organize` 的工具说明应与这一规则一致。

子代理的审计范围和结论受当前目标约束。主会话复核发现对目标的实际影响，再决定是否形成前置任务。保存交接材料只证明材料已存；普通任务协调需核实宿主操作、当前负责会话、接任回执和控制状态。维护请求仍按协议停止旧会话，由宿主转交，不能要求旧会话跨越转交继续业务。

## 验证方式

- 指令装配与工具说明测试：验证相关合同进入实际入口，不代表模型行为已被证明。
- 真实 Task 持久状态回归：用户明确修订后，当前规格替换、历史保留，旧进度不能冒充新验收。
- 现有接任/暂停回归：区分材料已存、已投递与已接收，保留失败重试及停止边界。
- 模型案例演练：输入脱敏历史场景，检查实际生成的计划及阻塞判断。演练不操作旧业务环境，不作为 Global 安装成功证据。
- 开发实例：安装实际构建包，核对加载来源、重启回执及既有入口可用。只发布到开发 profile。

完整脱敏案例、命令结果及发布事实存放于访问受限的 [A²D² 证据仓库](https://github.com/a2d2-dev/project/tree/main/dsh-plugin/docs/artifacts/issue-269-2026-10-28)。原始会话、私有推理、登录状态与凭据不进入源码或证据交付。

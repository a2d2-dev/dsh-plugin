# 搜索过滤下的 Project 层级与折叠回归

## 目的

用户在 #248 连续列表交付后反馈：过滤正常，但子项的会话和折叠功能似乎消失。检查范围为已有 Project 表格的父子结构、展开／折叠及会话导航；保留每批最多 100 行和既有查询边界。

基线为 `origin/main` 的 `6c22ac1`，独立修复分支 `fix/248-preserve-filtered-hierarchy`。不改变已完成 Task 的规格或自动执行状态。

## 复现与原因

在现有 DSH GUI 中，对同一批 28 条真实记录应用匹配整个仓库的搜索：折叠按钮从 3 个变为 0 个，会话入口仍是原来的 5 个。命令断言失败。最小生产组件回归用一父一子两条记录复现：搜索同时匹配两条记录后，预期一个折叠按钮，实际为零。

原因是共享表格把搜索、过滤、排序、分组、切片一并标记为 `transformed`，Project 标题单元格据此取消缩进、隐藏折叠按钮；查询分支也跳过了原先用于折叠的 `defaultRows`。数据和会话引用没有被删除。

## 修复

- 查询仍先应用真实搜索、列过滤、切片和排序；随后在各个匹配分组内部重建真实父子结构，并应用折叠状态；最后截取 100 行展示窗口。
- 当前分组内同时存在的父项和子项保留层级，排序作用于同级顺序。多值分组继续允许记录出现在多个组中。
- 仅匹配子项时独立显示，不补入不匹配父项；仅匹配父项且没有匹配子项时不显示无效折叠按钮。父项是否可展开由当前匹配结果确定。
- 会话单元格继续使用同一真实会话引用和原有导航行为；展开／折叠不发出工作写命令。
- 组件回归使用既有生产 TSX harness，补齐其 React Fragment 标记以消除无效组件警告。

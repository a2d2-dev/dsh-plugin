# Issue #248：100 行连续懒加载验收

## 目的

落实 [Issue #248](https://github.com/a2d2-dev/dsh-plugin/issues/248)：Project／Issue／PR 列表默认展示最多 100 行，滚动接近底部自动追加，每批最多 100 行；移除页码、上一页与下一页控件。与 [#246](https://github.com/a2d2-dev/dsh-plugin/issues/246) 的搜索和逐列交互配套，仅查询与展示。

基线为 `origin/main` 的 `fe1b0f8`（已包含 #247 列头交互），分支 `feat/248-infinite-lists`。本票没有原生子 Issue，实现、复核和验收全部属于原 Issue。

## 实现与范围

- 三种表格复用连续展示窗口：完整的本地查询先搜索、过滤与排序，再取首批 100 行；接近实际滚动面板底部 240px 时追加最多 100 行。查询、排序、切片、来源、视图及快照身份变化会重置展示批次，重复访问先前查询也从首批重新开始。
- Project 和 PR 使用已观察的快照／目录，继续保留原有字段、权限、保存视图及入口切片语义。Project 的完整成员扫描和 PR 的目录读取仍按现有来源接口工作，界面按 100 行逐批展示。部分 PR 目录展示完后明确提示“当前已观察目录已展示完；来源仍为部分观察”，不会把局部观察宣称为完整来源。
- Issue 请求默认 `perPage=100`；独立追加路径保留已有记录和同一表格实例，按节点身份合并，正在读取时锁住同批请求。失败保留已有行和原 continuation，明确显示重试入口；重试成功才推进 continuation。刷新从首批重新加载。
- 仓库 Issue 的 REST 页面包含 PR，单个原始页过滤后可能少于 100 个 Issue。后端通过生成的 GitHub 固定来源路径探查后续 Issue／尾部，修正恰好满页时误判还有更多，以及 PR-only 尾部的判断；不跟随远端提供的任意 Link URL。仍保留内部顺序页协议。
- Project 下的 Issue 追加读取同一个已完成快照，避免每批强制重扫。发现快照更换则重新读取首批，不混合两个快照。来源／查询导航使旧追加请求失效；旧成功和旧失败都不会污染新列表。
- 被动观察更新已有列表及末批元数据，不会把累计列表缩回一页。新增数据在同一帧扩展远端展示窗口，避免排序插入时暂时裁掉旧可见行；稳定行标识和滚动锚点维持可见内容位置。
- Issue 列搜索／过滤／排序／分组／切片明确限定为“已加载范围”。上方来源搜索和标签查询针对整个当前来源，保留原有文字匹配规则与限制。Project 查询针对当前完整快照视图；PR 查询针对当前目录并显示完整性。

已有来源能力的边界继续保留：PR 目录的扫描上限／部分引用标记及 Project 扫描边界不被本票改写。仓库 REST 按更新时间分页，遍历期间远端成员或排序字段发生修改时应刷新观察；身份去重不能提供 GitHub 未提供的冻结快照。稳定来源的正常遍历与重试已覆盖无漏项、无重复。

页面验收发现并修复了两个自动测试未覆盖的问题：观察器使用视口作为根节点时，被面板裁剪挡住了提前加载阈值；排序追加的中间 100 行窗口曾造成 310px 锚点偏移。最终构建分别以实际滚动触发和 0px 锚点偏移复验通过。

自动化曾遇到刷新恢复面板后再次点击入口将其关闭、离屏坐标点击未触发、空字符串 fill 未清空输入，以及验收脚本选择器转义错误；均核实后修正操作或脚本，失败没有计入产品通过证据。

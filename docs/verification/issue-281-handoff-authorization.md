## 根因与排除

1. **Confirmed：Agent 新增限制且来源混淆。** S1 自己编写禁止句并发送，S2 接收同文，最后明确误归因给 LF，四个环节闭合。
2. **Confirmed：将历史现状、身份接续边界扩大为业务限制。** “本轮只读检查”“已完成 Task 不能追加材料”都是真实事实，但不能推出“LF 禁止重新禁用插件”。真实 Task 终态限制仍须遵守，不能借业务授权绕过。
3. **Refuted（已核会话内）：LF 后来收紧启停授权。** 没有相应真人原文，真实后续消息反而要求推进、禁用截图并纠正提示词。
4. **Not supported：当日插件固定模板直接生成该句。** 实际为 Agent 用浏览器普通输入；当前 `/handoff` 也曾把合成消息标为 user，是相关机制风险，不能冒充当日直接入口。

## 修复原则

交接同时传递已授权操作、真实用户限制和恢复义务；限制保留原消息指针及适用阶段。执行现状和维护回执要求有各自范围，不能改写为长期业务禁止。材料明确标注由源会话 Agent 编写，普通 GUI 的 user 运输角色不作为人类授权证据。正式消息来源与真实用户来源分别记录。

真实用户后来只读、暂停、停止、不卸载等要求仍然优先；权限配置、Task 终态和接任资格继续遵守。本修复不自动扩大授权，也不解除用户的真实停止。

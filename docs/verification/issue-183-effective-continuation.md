# #183 项目默认接续真正生效

## 目的

使未单独保存接续策略的既有执行实际继承项目当前默认，在安全步骤边界达到软目标后自动交接。300000 token 是提前接续目标，运行工具不会被强行中断。

## 根因与改动

页面已展示 `执行策略 ?? 项目策略`，运行时却只读取执行策略。项目后启用自动接续时，历史执行没有策略，步骤检查和后台观察直接返回，因此页面显示启用，实际从不计量或预约接续。

步骤检查、正式计量、操作恢复和源会话预留检查统一读取有效策略。执行明确关闭仍优先；未保存执行策略时，项目默认修改立即适用。项目策略保存只清理本项目继承执行的旧计量和策略阻碍，使修正后的设置能够重新计量；不改执行独立策略、控制状态或接续 operation。新执行仍保留原先的启动默认快照，不在本次改变继承语义。

异步计量提交时复核完整有效策略，项目修改或执行保存覆盖都不会提交旧策略下的读数和预约。项目和执行版本继续独立递增，执行首次保存仍从版本 1 开始。页面继承表单在项目默认版本变化时刷新，并准确说明继承范围。

保留后继首次计量已达目标的 `continuation-target-too-small` 防循环保护。历史后继缺少旧计量时，无法仅凭当前高读数证明其初始材料足够小，本修复不跳过保护。既有超长历史会话需要明确手动交接后再进入自动接续链路。

1. 使用真实 WorkApplication、DSH AgentLoop、工具和 JSONL 持久化创建执行，再通过正式命令启用项目默认，执行没有独立策略。
2. 人工及自动消息分别启动长 turn；两个真实工具完成后读数从 100 越过 300000，下一业务请求被挡住。协调后同 Execution/owner、epoch 1 → 2、唯一后继、材料 received，后继实际接收业务输入。原完整自动 envelope 保全。
3. 验证继承执行响应项目目标从 300000 改到 200000；明确 disabled 的执行不被默认启用。异步计量期间项目关闭，旧读数不得提交。
4. 将项目策略设成超出真实窗口的值，确认真实策略阻碍；修正默认后原执行可重新计量并预约，不修改独立覆盖。

# #124 GitHub Issue 来源 UI 架构

## 背景

本片从 merge HEAD `c5cdd4b9e8ef42c1d66dfef828162e9b6c819866` 开始，已包含来源后端 `875c528` 与 HTTP UUID 修复 `256b9f8`。原客户端的 Issue 标签只有静态占位，HTTP 客户端还会丢弃失败响应携带的缓存内容和已有工作定位，因此用户无法从已有 GitHub 工作进入本地工作面板。

本片沿用[来源应用契约](./a2d2-v3-124-source.md)与[本地事实决策](../adr/0003-local-work-records-and-optional-collaboration.md)，开发集成目标为 `spec/dsh-control-panel-v3`。后端复核修复通过精确提交 `2905589fa2e39f7861930795ca7d4a29cbce709a` 合入，没有重做来源实现。

## 目标

- 在具体本地 Project 中配置 GitHub owner/repository，辨认实际来源账号并浏览完整 Issue。
- 区分缓存、刷新失败、未观察页、空页与停用状态；浏览不会创建本地工作。
- 显式接入或关联已有 Task，通过公开命令保存事实后进入原有四标签详情，并保留来源位置。
- 保留已接受内容、已确认验收及既有 Session；新观察不替代本地完成与协调权。

### 非目标

完整 GitHub Project views（#125）、远端写入、任务启动／执行（#122）、旧记录迁移、部署及预览更新均不在本片内。当前 Issue 标签展示仓库来源，不宣称应用 GitHub Project 的视图配置。真实目标仍为 [a2d2-dev Project 1](https://github.com/orgs/a2d2-dev/projects/1) 中的 [Issue 112](https://github.com/a2d2-dev/dsh-plugin/issues/112)，没有使用其他 demo 代替。

## 架构

### 概要设计

控制面板中的 Issue 标签进入同一个根控制器。来源配置、列表和详情均调用原有 `/a2d2/api/work`；只有“接入为本地工作”和“关联已有本地工作”触发来源接受命令。服务端返回的 TaskRef 决定详情导航，Issue 编号不用于拼接本地身份。

### 架构设计

`WorkPanelController` 保存来源、过滤、分页、完整 Issue、缓存标记与错误，原有 Task 详情仍使用概览／会话／相关工作／活动四标签。根状态不会随面板卸载或原生 Session 往返丢失。跨项目命中已有工作的定位时，保存原来源位置；详情返回恢复来源项目、筛选和页码。显式切项目则清除旧来源上下文。

来源请求拥有递增代次；切项目、换查询及返回列表使旧结果失效。打开来源还会使在途 Task 详情导航失效，防止迟到的详情重新抢占界面。命令使用既有 `browserUUID()` 的 CSPRNG；未知网络结果重试复用 commandId，HTTP 环境不依赖 `crypto.randomUUID()`。

GitHub 标题、正文、标签与身份均为 React 文本节点，不解释 Markdown 或 HTML。来源链接只允许无凭据、无端口、无查询或片段的 `https://github.com/<owner>/<repo>/issues/<positive number>`，使用 `noopener noreferrer`；危险 URL 不生成链接。

`WorkClientError` 保留失败响应中的来源、最后观察与已有工作定位。相同查询刷新失败时保留已显示内容并标记缓存；换过滤或页码时不把上一查询的数据假装成新结果。`source-page-unobserved`、权限错误与网络错误独立显示，不能落成空列表。身份明确为“最近确认的凭据身份”，不把缓存身份误称为新凭据验证。

### 组件模块

| 组件 | 职责 | 输入／输出与状态归属 |
| --- | --- | --- |
| [HTTP 客户端](../../src/client/work-api.ts) | 同源应用边界与结构化失败 | WorkQuery／WorkCommand → WorkCompleted 或保留 WorkFailure 的错误；无持久状态 |
| [根控制器](../../src/client/work-panel-controller.ts) | 来源浏览、接受、导航与代次屏障 | SourcePanelState 与本地列表状态属于面板；命令持久事实属于 WorkApplication |

| [来源应用](../../src/work-sources/application.ts) | 身份去重、原子接受与观察保存 | 已接受快照／最新观察／Task／Session 关系属于本地工作快照 |

### 数据流程

1. 用户选择具体本地项目，在 Issue 标签配置 owner/repository；`source.configure` 保存范围，随后显式读取该来源。
2. `source.issues` 以 `@me/open/page:1/perPage:20` 起始；`@me` 使用返回的真实凭据账号。可切全部负责人及远端状态，按服务端 `nextPage` 翻页，或输入 Issue 编号打开详情。
3. 点击条目通过 `source.issue` 读取完整原文。启用来源时读取远端，停用时读取缓存；手动缓存按钮使用 `refresh:false`。
4. 接入发送 `source.import`；关联已有工作发送 `source.link` 和真实 expectedVersion。成功后的返回定位进入本地详情；已有归属冲突显示“打开已关联工作”，不复制 Task。
5. 概览显示结构化验收待确认与空正文待补充提示，并分别展示已接受来源、最新观察及变化字段。Session 仍由原有公开关联命令与宿主导航处理。

## 场景

### 从真实 Project 1 的已有 Issue 接入

**前置条件**：本地项目已存在，DSH 登录有效，服务连接的 GitHub 账号有 `a2d2-dev/dsh-plugin` 读取权限。Project 1 已只读确认包含 Issue 112；此 UI 不读取或仿造完整 Project view。

**操作**：A²D² 控制面板 → 选择当前项目 → Issue → 配置 `owner=a2d2-dev`、`repository=dsh-plugin` → 保存并读取来源。确认最近凭据身份；按需要切“全部 Issue”，或在编号入口打开 `112`。详情展示完整原文、负责人、标签、远端状态及观察时间。单纯浏览后本地 Task 数量不变。

点击“接入为本地工作”后进入原四标签详情；结构化验收标准显示尚待确认，不能因为原文中存在验收段落而推断已满足。已观察 Issue 的 `body:null` 与空字符串均是合法空正文，允许显式接入，并保存 `missing:['body','acceptance']`；没有 Issue 观察则不提供接受动作。

**数据走向与完成判据**：GitHub 只读观察 → 来源详情 → 显式接受命令 → 本地 Task/ExternalBinding → 原详情；浏览不写 Task，接受后有稳定本地身份与完整已接受内容。

### 关联已有工作并进入真实 Session

在 Issue 完整详情选择当前项目的已有工作，点击“关联已有本地工作”。后端校验其版本后增加外部关联，不覆盖已有目标、规格、验收或 Session。在原会话标签中选择兼容 Session 进行关联，或直接打开已关联 Session。打开 Session 不授予协调权；从 Session 工作入口返回同一个 Task。

来源详情、Task、Session 往返保留来源筛选与分页。跨项目已有归属通过返回的定位进入对应 Task，返回后恢复原项目来源位置，不生成另一份工作。

### 刷新失败、来源停用与离线续读

刷新按钮显式发送 `refresh:true`；权限不足、缺凭据、限流与暂不可用显示具名失败和可取得的重试时间。存在最后已知内容时保留并显示缓存标记；空页只有在有成功列表投影时才作为空页显示。原始 GitHub 页可能全为 PR，空页有 `nextPage` 时仍可继续翻页。

点击“停用来源”发送版本检查的 `source.set-enabled`。界面禁用远端刷新与新接受，缓存列表、缓存详情、已有 Task 与会话仍可读。重新启用不自动刷新或启动工作。离线重新加载 Task 详情直接查询已接受本地工作，不依赖 GitHub 凭据。

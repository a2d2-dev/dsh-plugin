# #122 UI：执行观察与当前会话

## 背景

详情原先只读取 `task.detail`，固定显示尚未开始。此片接入已提交的 `task.execution`；保留项目导航与概览、会话、相关工作、活动四标签。

## 目标

- 展示执行状态、实际环境、进展、控制确认及事件投递事实。
- 只从执行权威取得当前会话；任务/项目切换隔离迟到响应。

### 非目标

启动表单、options/catalog、固定 kickoff、手动接续和历史只读投影等待稳定接口；不引入轮询。`completed` 回执不表示 Task 完成。原生会话反向入口沿用已有 `session.work`，不通过扫描猜测 execution 归属。

## 架构

### 概要设计

controller 按同一 TaskRef 并行读取详情与执行，统一代际和 AbortSignal，分别保留查询失败。切换 Task/Project 或返回列表取消旧详情读取，刷新时清除旧执行与入口，完成后原子发布两份结果。

### 架构设计

无 execution 表示未开始；accepted/creating/ready/running/waiting/paused/failed 分别显示已登记、创建中、就绪、处理中、等待、暂停、失败。此片标注“执行状态”，只代表持久执行事实；base 没有宿主实时运行读数，不宣称模型此刻正在运行。具名执行错误和查询错误可见。actual 缺失时不把请求配置展示成有效环境。

当前入口必须满足 actual 已确认、runtime 匹配、TaskRef 匹配，且处于 ready/running/waiting/paused。点击时再次核对 controller 当前快照，再调用既有 openSession。accepted/creating/failed 不提供入口。related/review 仍独立展示并保留普通宿主导航，不宣称历史只读。

### 组件模块

| 组件 | 职责 | 权威来源 |
| --- | --- | --- |
| WorkClient | 同源、操作者授权的查询 | 已提交 WorkQuery |
| WorkPanelController | 查询代际、取消与当前入口校验 | task.detail / task.execution |
| WorkPanel / CurrentExecution | 状态与事实呈现 | controller 快照 |

### 数据流程

详情导航 → 同 TaskRef 两个查询 → controller 检查代际及取消 → 原子更新 → 概览/会话呈现。输入 accepted/delivered/consumed 与 acceptance=unassessed 分别显示；控制 accepted 显示等待生效，只有 applied 显示已生效。

## 场景

### 接入与浏览

前置：集成真实插件 bundle、操作者授权及已有 Project/Task。打开 A²D² → 选择项目 → 工作详情；概览显示保存材料及执行事实，会话标签分开显示当前与关联会话。可进入时点击“进入当前会话”调用宿主导航。返回项目内容保留搜索/筛选，关闭面板沿用原会话。

### 失败与恢复

执行查询失败显示服务 code/message，保存规格仍可读，入口不可用；点击“刷新详情”重新查询。创建失败显示 execution.error；此 UI 片不擅自启动恢复。切换项目后旧请求即使迟到也不能替换新详情。

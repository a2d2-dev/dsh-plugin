# A²D² v3：DSH 内工作控制面板与连续执行

**状态：已由 LF 确认测试设计、9票粒度、依赖及发布，主任务为 [#120](https://github.com/a2d2-dev/dsh-plugin/issues/120)。** 本规格沿用当前 ADR，不重新讨论已定概念。文案、密度和字段排列可在实现中细化。实际工单与关系见[发布记录](a2d2-control-panel-v3-tickets/publication-result.json)。

## Problem Statement

研发已经在 DSH 中使用会话、skill 和开发流程。工作从项目中分配的 Issue、线上 Bug 和本地需求进入，但用户需要反复搬运 Issue、询问当前进展、整理拆解关系，以及在上下文过大时手工准备新会话。

把这些工作搬进一套独立流程管理应用会增加学习和切换成本。用户需要在原有 DSH 内看清“处理什么、当前由哪个会话处理、哪些子工作完成或受阻”，并按明确范围启用持续接活与自动接续。GitHub 是高频入口，但不应阻止本地项目、任务和验收闭环。

## Solution

在 DSH 侧栏增加一个 A²D² 控制面板入口，保留现有项目分组、会话和对话。用户先选一个具体项目，再浏览 Issue、PR 和项目视图；列表连接到独立工作详情和真实会话。

Issue／本地工作详情采用已确认的紧凑布局：顶部标题与操作，下方“概览、会话、相关工作、活动”标签和全宽纵向分区。概览只显示状态、描述、当前会话与待确认项；接续历史和评审会话在会话标签区分，工作拆解与 PR 在相关工作中展示。

用户可对单项工作开始处理，或对固定来源规则启用持续处理；系统复用已有执行，不重复接活。自动接续在合适的宿主安全边界转到后继，并保留具体决定和恢复记录。任务验收完成后收口本地执行，外部 Issue 关闭作为可独立恢复的协同动作。

## User Stories

1. 作为使用 DSH 的研发，我希望只增加一个工作控制面板入口，以便继续使用原来的会话、skill 和项目分组。
2. 作为研发，我希望打开或关闭面板不改变当前会话，以便随时回到刚才的对话。
3. 作为研发，我希望项目下拉始终选中一个具体项目，以便所有列表和动作都有清楚的范围。
4. 作为研发，我希望从既有工作空间接入业务项目，或建立没有仓库的本地项目，以便不必为使用插件重建工作环境。
5. 作为研发，我希望没有在线会话时也能浏览已经保存的项目与任务，以便工作状态不依赖某个窗口仍开着。
6. 作为研发，我希望项目、任务和负责 Agent 在关联 GitHub、换目录和接替会话时保持身份，以便不重复创建或执行同一项工作。
7. 作为研发，我希望从所选项目读取分配给我的开放 Issue，以便接着处理既有工作列表。
8. 作为研发，我希望首次接入保存目标、描述及验收依据，以便远端暂不可用时已有工作仍可继续。
9. 作为研发，我希望添加无 Issue 的本地工作并记录规格、验收和证据，以便不涉及 GitHub 的任务也能闭环。
10. 作为研发，我希望重复输入同一 Issue 或子 Issue 时回到既有工作和上下文，以便不会出现第二份执行。
11. 作为研发，我希望看见来源权限、最后同步结果和暂不可用原因，以便分清“没有工作”和“数据没有取到”。

## Implementation Decisions

### 1. 领域身份和记录

- 采用稳定 ProjectId、TaskId、ProjectAgentId、ExecutionId 和带 runtime 的 Session 引用。外部身份独立映射；业务项目与仓库、工作目录和 DSH Workspace 分开。
- 本地记录至少包含任务目标、规格、验收标准与结果、证据、负责 Agent、业务进展、父子关系、执行关联、完成操作和外部最后观察。单独一个远端链接不满足本地可接续条件。
- Project Agent 从项目默认职责与模板渐进接入，不要求普通用户先进入 Agent 管理页。执行时固定有效策略与资源，不能通过切项目改变已有会话配置。
- 来源对象唯一性按 provider 与规范化后的真实外部身份校验；同仓库子 Issue 已在拆解中出现时也参与查重。裸 Issue number 不能跨仓库使用；有稳定外部节点身份时以它为准，URL 只是可读引用。
- 存储适配必须通过领域版本、原子唯一索引与命令去重契约。优先复用现有持久化设施；具体本地介质由首个切片依测试证据选择，不预先假定 GitHub 或多个文件写入具备事务能力。

### 2. 宿主内控制面板

- 使用 DSH 公开整页插槽和 panel entry，保留原会话区域；面板自己的项目、主标签、详情标签与返回位置不覆盖当前宿主 Session。
- 项目选择是查询操作，不创建空会话、调用模型、领取任务或切换执行目录。首次没有 Project 时显示接入已有资源／创建本地项目入口，不提供“所有项目”或伪造默认业务项目。
- 新查询按服务端 ProjectId 工作，无在线会话也可读。浏览器只提交领域和资源引用，服务端解析允许范围；不接受任意 cwd 作为项目查询权限。
- 已关联的原生 DSH 会话保留对话与输入框，并提供一个轻量的关联工作入口，显示项目/任务、进展和接续状态，能回到正确详情。未关联会话保持原状；旧/新会话都链接同一 Task，查看历史不更换当前协调指针。
- Issue 与本地工作共用详情结构。当前处理会话由有效协调关联决定，接续历史按关系排序；独立评审会话不会修改该指针。
- 历史查询必须阻止旧会话继续驱动该 Task。若普通宿主导航没有只读能力，提供只读记录投影或正式宿主只读接口，不能仅换一个标签就宣称历史不能执行。
- 首期保留面板内返回语义，不把宿主 panel 导航接口扩张为已具备 URL 深链和浏览器历史路由的承诺。

### 3. 工作应用命令与执行协调

- 统一高层工作应用接口提供创建／接入、规格与拆解更新、父子关联、指派、关联会话、启动或复用、等待/暂停/恢复、手动接续、证据与标准结果记录、验收完成、同步重试和查询。写操作携带 commandId、目标领域引用及必要的 expectedVersion，返回 accepted、running、completed、conflict 或具名失败。
- 这些意图必须有真实可调用的模型工具或受信任 UI 命令，不依赖测试 fixture 私造数据。无 Issue 子 Task 通过父 TaskRef 创建；业务进展、提问与证据更新校验负责者/执行权限。验收结果绑定标准版本，规格改变后不能沿用失效的通过结论。
- 指派、Binding、执行资格和宿主启动分别存事实；用户可通过一次“开始处理”意图编排，失败后能辨认已提交的步骤。
- 同一协调域内一个 Task 仅有一个有效 owner/epoch；首期一个 Session 也至多协调一个活动 TaskExecution。两个方向的并发检查必须原子或有等价串行保证。
- 首期只支持单宿主、同 PID 命名空间和同一协调权威；跨机器共享锁和共享协调会话不在本期开放。
- 真实会话创建、模型选择、preset、权限和 cwd 继承使用公开宿主接口。对已有会话的关联只在环境和归属校验后成立，不静默重配其模型或权限。
- 复用已有分步交接、固定后继、消息 ID、inbox 与维护边界。新 TaskRef 下的手动接续和完整 prepare/write/create/take/deliver 恢复原语随单项运行切片落地，之后旧活动记录迁移和自动策略都复用它。运行器因浏览器关闭仍可继续；重复请求或回执未知先核对已有操作。
- 一次 CLI run 与持续子会话分别建模，能力不足显式拒绝；失败重试保留原结果，核查副作用后创建新尝试。

### 4. 上下文策略

- 200K／300K 表示用户希望提前接续的软目标，单位明确为 token；不承诺任意模型接受这些值，也不承诺单个长 turn 永不跨越目标。
- 项目保存默认策略；启动或显式修改已有执行策略时记录有效版本。关闭自动接续不取消已授权的手动接续，也不改变 DSH 自己的独立压缩配置。
- 在安全边界结合公开 token measurement、实际路由、模型窗口、有效输出预留和接续余量评估目标。有效触发目标不大于窗口扣除预留后的可用空间；非法配置报错，不静默把无法容纳的 300K 当安全值。
- 保存计量来源、日志版本、时间与路由；缺值、估算、过期和动态路由变化可见。预算守卫按下表处理，明确限制的是自动推进，不拦截只读查询、策略修正和受控手动接续。
- 等待人类、未结算的相关原生子执行或宿主未提供安全维护边界时，显示“待安全接续”及原因。独立子 Task 的存在本身不阻止交接。
- 接续前保存目标、具体决定、证据、待办和下一步，不无限复制整段对话；必要引用须本地可解析。新会话接任后才更新当前入口，原会话退出协调资格。
- 长 turn、大工具输出、自动压缩和路由变更可能延后触发；界面准确显示延迟。硬性最终请求预算准入属于额外宿主契约，不混入本期软目标承诺。

#### 预算状态与退化行为

| 条件 | 自动行为 | 保留的动作与恢复 |
| --- | --- | --- |
| 有效容量、明确输出预留和正的接续余量，计量为当前 usage 或 estimated | 允许软目标判断；estimated 明示估算，不因没有精确 tokenizer 一律暂停 | 未到目标按授权推进；达到目标进入待安全接续 |
| 计量过期或实际路由变化 | 先用公开接口重新测量和解析当前路由；完成前不发起下一普通自动工作 turn | 查询、补充信息和策略修改可用；重新校验成功后进入可调度状态 |
| 缺有效窗口/输出预留/计量能力，或重新测量仍不可靠 | 当前 Task 标为预算信息受阻，暂停其下一普通自动 turn；来源规则可以推进其他合法候选 | 不清除执行身份；可修复元数据/策略或显式请求手动接续。守卫不自行批准模型请求，更不把未知值当零 |
| 保存的新目标合法，但已低于当前计量 | 不再发起普通自动工作 turn，安排下一安全边界接续 | 显示待接续；人工请求和未消费消息保留 |
| 模型换小后，原目标/预留组合不可容纳 | 标为策略需重验，暂停该 Task 普通自动推进，展示可选上限 | 修正策略或手动接续；不静默把原值当成仍安全 |
| 元数据恢复且策略重验通过 | 受管 Task 进入 ready；若属于队列，按串行调度取得可推进槽位后继续 | 人主动暂停的 Task 不自动恢复，须明确 resume |

手动接续使用同一安全边界与固定操作身份，不被自动软预算守卫循环拒绝；若接续材料无法生成或实际请求失败，保持可见受阻/恢复状态，不强行接任。接续余量须有明确的正值及策略版本，默认值由实现按实际指令/工具开销验证，不能缺省为零。

### 5. GitHub 来源、视图与 PR

- 第一适配目标为 GitHub.com。凭据只在宿主解析，DSH 登录与 GitHub 仓库／Project 权限分别检查；来源不可用不使本地记录不可读。
- 浏览远端列表不必自动创建领域 Task；接入、关联或开始处理时，保存规范化外部映射及被接受的内容快照，再使用同一领域命令。已接受的本地工作可在来源离线时继续。
- 每个 Project 可关联仓库来源和一个用于视图的 GitHub Project；本地视图也合法。源视图标签来自 API 的 name/filter/fields 等能力，示例中的五个标签不是产品常量。
- 支持分页、游标、最后观察和权限错误。远端筛选尽量交给来源 API，尤其 @me 绑定当前来源身份；不支持的布局、字段或排序明确展示降级，不偷偷换成全列表。
- Project 内容按类型分流：Issue 进入工作详情；PR 进入 PR 详情；draft 明确标示为草稿，可只读查看或显式接入本地工作；不可见/缺失内容显示受限原因，不伪造 Task。远端正文按不可信内容安全渲染，仅作为任务材料，不能扩大权限或替换宿主指令。
- Project 视图切换只改变所选项目内的查询；搜索、标签、字段和空状态与当前视图一致，换项目清除不适用的条件。
- PR 目录和关联数据由来源适配取得；现有 PR watch 仅用于已知 PR 的变化观察。PR 评审会话使用有用途的绑定，并按 Task+PR+用途复用，不能抢占协调身份。无关联 Task 的 PR 允许查看；评审前显式选择既有工作或接入本地工作，不伪造 Issue，也不因 PR 必须有任务而隐藏它。

### 6. 持续处理

- 保存单个项目、来源和筛选快照、排序、方法、执行资源及启用状态。来源视图规则变更若扩大授权范围，需显式更新规则，不能悄悄接入新的工作范围。
- 首期一个规则至多有一项正在自动推进的工作；该可推进槽位不同于 Task 的协调资格。已有可推进执行先复用，待确认、待评审或明确等待的工作持久保留并让出槽位，使规则能接下一项。
- 等待不会撤销 Task 的 owner 或重建会话。回复/结果到达后先记录事件并进入 ready 候选，按规则的串行调度重新取得可推进槽位；事件投递不能绕过规则并发门槛直接唤醒另一项自动执行。用户主动暂停须显式 resume。
- 等待/让出须到宿主安全边界；仍有在途工具时先显示请求已接受，不能立刻宣称已停止。普通原生回复也经过当前 Task 的恢复与调度边界，不隐式增加规则并发。
- 发现 → 唯一映射 → 候选记录 → 版本化领取 → 启动或复用均可恢复。重复发现、重复点击、两个消费者与启动回执丢失汇合到同一 Task 和固定执行身份。
- 暂停接新工作在 claim 边界生效；已合法领取的工作可继续。用户要停止当前执行时走独立控制路径，不能声称已撤销在途外部副作用。
- 当前 Task 等待时安全让出可推进槽位，或验收完成并收口后退出规则；随后调度下一合法项。完成后的 Issue 关闭待同步不占用模型或阻止下一项。
- 来源轮询／推送及游标属于确定性适配，不依赖浏览器保持打开或模型不断提问“还有任务吗”。断线恢复保留候选与领取记录。

### 7. 完成、通知和外部同步

- 负责 Agent 通过实际可调用的领域命令/模型工具记录证据、标准结果与结论；必要子工作和仍在运行的相关委派按验收规则核实后，才保存完成事实。纯本地父子工作必须能够从创建、指派、记录证据、完成子 Task 到父收到结果完整通过该入口，而非仅在 fixture 中构造。
- 完成事实与后续操作意图可靠提交，再执行收口、父通知和外部关闭。父任务不能在子任务尚未提交完成时先收到不可撤回的“完成”事实。
- 完成、投递、消费与远端关闭分别确认。外部 close 成功但回执丢失时先查询原对象与操作结果；不再次创建任务或重启执行。
- 外部负责人、关闭或重开观察先比较版本与权限；冲突可见，执行中更换负责人须到安全边界。完成任务不因远端仍 Open 自动回退。
- 停用协同／解除关联保留本地内容、映射历史和队列，停止相应外部发布与导入。恢复后按上次版本调和，不删除远端对象。

### 8. 兼容迁移与版本

- 从已核实开发代码建立实现分支，固定宿主公开能力矩阵。旧 main 不包含全部运行器改动，不能把分支差异当缺失功能重新写一遍。
- 新记录版本与旧 writer 隔离；旧入口先解析稳定映射，再进入同一新命令。保留旧 Task/Issue 地址、Session、固定后继、message ID、inbox 和 watch 关系。
- 活动工作只在安全边界切换权威；先备份、建立迁移日志与校验，再启用单一新 writer/runner。碰撞或不明归属停止迁移并显示原因。缺验收材料的历史完成项保留历史来源与证据缺口，不伪造新验收结论或重新启动。
- 新数据产生后回退必须停新执行并进行兼容导出或恢复备份；禁止直接启动旧 writer 丢弃新字段。此升级流程是有独立验收的纵向切片，不要求立即在本次规格阶段迁移真实数据。

## Testing Decisions

### 主要接缝

以工作应用的公开命令与查询为主要行为接缝，覆盖真实本地记录和 DSH 执行适配；浏览器测试在真实隔离 DSH 外壳与插件 bundle 上验收导航、动作和状态。两者分别证明领域行为与宿主交互，不用大量内部 CRUD mock 代替。

- 工作应用合同测试使用稳定 commandId、领域引用、版本条件；真实持久化、锁、日志和恢复步骤，模型与 GitHub 采用可控适配。
- 浏览器 lane 使用独立 home/profile/记录、真实插件与会话／workspace；无模型需求的测试禁用模型适配器，误调用直接失败。
- 延用现有运行器安全维护、固定后继、inbox 回读和 preset 组合测试的先例，并明确旧测试中仍存在的控制器或模型选择替身。
- 真实 GitHub 验收分层：只读来源 smoke 验证实际权限、分页和视图；写操作只在专用测试对象中授权进行。测试替身返回成功不能替代此证据。
- 真实模型接续验收独立记录：具体决定是否可被后继恢复、资源与有效策略是否正确；不把原型的静态摘要当真实模型质量保证。

### 必须可外部观察的验收

| 编号 | Given / When | Then |
| --- | --- | --- |
| A01 | 无 GitHub 的本地项目创建工作并关联真实会话 | 目标/规格/验收本地可读；稳定 ID；可以正常进入会话 |
| A02 | 打开面板、切项目或返回会话 | 原 DSH 界面保留，不创建空会话、不发送 prompt |
| A03 | 不同项目含同号 Issue，或同一子 Issue 重复导入 | 不串项目；相同外部对象不复制 Task 或启动第二会话 |
| A04 | 两个消费者领取同 Task，或两个 Task 抢同 Session | 至多一个有效 Task owner，同 Session 不同时协调两项工作 |
| A05 | 宿主已创建会话但回执丢失，客户端重试 | 查询并复用固定执行/会话身份 |
| A06 | 主会话接任、打开历史、创建 PR 评审 | 只有真实接任更新当前指针；历史不可驱动旧 Task；评审独立关联 |
| A07 | token 目标在实际模型可用范围内或超出范围 | 合法策略生效，非法策略拒绝；来源/估算/未知状态可见 |
| A08 | 长 turn、大结果、路由变小、缺计量或自动压缩 | 不假报硬安全保证；待接续原因、阈值和有效读数一致 |
| A09 | 交接步骤任一恢复点失败或重启 | Task/Agent/Stage 不变，复用后继和消息身份，旧协调者失权 |
| A10 | 等待输入或子执行，随后结果进入 | 不空推；接受、消费与验收分别记录；结果投递有效协调者 |
| A11 | 项目视图、标签、搜索和分页切换 | 展示真实视图对应内容，换项目清理旧条件，空结果与失败区别明确 |
| A12 | 来源分页中断、重复/乱序事件、暂停与 claim 竞争 | 不漏已提交候选、不重复执行；暂停边界可解释 |
| A13 | 本地完成提交与收口/父通知之间中断 | 父可见的完成有可靠事实依据，恢复不重复通知或启动 |
| A14 | 外部关闭失败或成功但回执未知 | 本地仍完成；先核对后补同步；不重跑任务 |
| A15 | 外部改负责人/重开已完成工作，或停用协同 | 不绕过锁或倒退本地事实；保留冲突与未完成操作 |
| A16 | 旧记录迁移中断后重试，或新旧 writer 同时存在 | 映射与操作身份稳定；阻止双写；可诊断回退边界 |
| A17 | 未登录、跨项目引用、任意目录输入或缺后端能力 | 在业务副作用前拒绝；错误可见且不泄露凭据 |

良好测试断言用户能观察的状态、数据和副作用次数，不照抄实现分支。注入点围绕实际跨边界提交窗口；不用增加超时、盲重试或省略失败来让用例变绿。

## Out of Scope

- 重做 DSH 聊天、项目侧栏、工具执行或模型系统；不把独立 HTML 直接提升为生产实现。
- 跨全部项目的汇总／执行入口、多租户 RBAC、多主机全局锁、同一协调会话并行管理多 Task。
- 任意 CLI 的持久会话化、跨主机迁移、成本路由和价格优化。
- 完整 GitHub UI 克隆、所有筛选语言的本地重实现、任意外部字段双向同步、GitHub Enterprise 首期适配。
- 自动合并 PR、发布版本、生产部署或修改 18780/18781 服务；具体任务若要求这些动作，仍按自身授权与验收处理。
- 下一个最终请求绝不超窗的硬预算保证、准确 tokenizer 承诺，以及迁移宿主内部压缩机制。
- 用固定示例数据冒充真实来源、用运行退出冒充验收、用页面刷新成功冒充宿主执行成功。

# v4 原型整体交付规格

任务 #136（父 #120），主会话 session-25bef557-597a-4418-96e4-7727946f1d20。LF 2026-10-21 直接指令：参考 v4 原型完成整体工作，将此前仅原型讨论推进为产品实现、验证与交付。v4 是原型迭代号，领域继续沿当前 v3。

## Problem Statement

用户需要从 GitHub Project 或仓库中的 Issue 进入真实处理会话，在一处观察协作执行，并通过可保留决定的接续和自然语言持续委托推进工作。当前实现已有启动、自动接续与结构化持续规则，但来源入口、统一执行和委托计划与原型仍有差距。

## Solution

沿用原生 DSH，会话与工作由现有领域身份关联。来源顶栏支持 Project／仓库链接识别、确认添加、唯一标签与概览；Project 来源展示概览／项目／Issue／PR，仓库展示概览／Issue／PR。Issue 首次开始创建或复用唯一 Task 和真实执行，之后始终进入有效当前会话。详情统一呈现独立子 Issue、协作会话、后台作业、待确认及历史；接续正式接任才切换当前入口。用户用自然语言委托，先查看真实模型生成的有序计划，明确开始后由服务端校验及原有调度执行。

## User Stories

1. 研发可以粘贴 GitHub Project 或仓库链接，并在添加前看到真实名称、类型、账号和访问结果。
2. 同一规范来源复用标签，Project view／切片入口得到保留；切换来源默认进入概览。
3. Project 来源具有概览／项目／Issue／PR，仓库来源具有概览／Issue／PR，视图与条目来自真实数据。
4. Project 视图与 Issue 独立筛选分别生效；缓存、读取中、权限失败、不可用和有效空结果可辨。
5. 同一 Issue 跨来源复用已有 Task 和当前会话，重复点击不重复启动。
6. 父 Issue 下的子 Issue 保留自己的负责人、处理入口和验收，父子任务与会话父子分别呈现。
7. 会话与执行页统一呈现当前协调、实施、评审、后台工作及执行归属。
8. 已替代／已处理失败进入历史，待收结果、已投递、已消费和已验收分别展示。
9. Issue 和聊天具有接续页，直接查看策略、上下文观察、准备／收取结果／接任阶段及历史。
10. 后继准备时原段仍负责，正式接任才改变入口；失败重试复用后继，决定、证据、待办和下一步保留。
11. 聊天保留单标题，紧凑关联任务入口返回正确详情，上下文归指示球承载。
12. 用户自然语言委托持续处理，预览模型生成的顺序、理由、下一步及新建／复用会话方式。
13. 用户以自然语言重新安排，持久 Block 名单约束所有后续计划，界面不要求手工排序。
14. 查看计划不启动工作；明确开始才启用，切来源不改变既有规则范围。
15. 暂停只停止后续接入，在途工作保留收尾；等待项保留身份并安全让槽。
16. 关闭浏览器及重启后来源、委托、计划、Block、执行和接续仍可恢复。
17. 任务先完成本地验收，再收口、通知父工作并同步外部关闭；同步失败独立补偿且不重跑。
18. 子 Issue 各自验收后父任务才能完成，PR 合并不替代任务验收。
19. 建议只填输入框且保留草稿，不代用户发送消息。

## Implementation Decisions

- 复用 WorkApplication 公共命令／查询、事务存储、TaskRef／ExecutionId、owner／epoch、固定会话和分步接续。不另建平行运行器，不从标题或最新时间推断控制权。
- 来源是浏览范围，外部 Issue 的 canonical 映射跨来源复用。跨领域项目进入既有工作并显示归属，不创建副本。
- GitHub 读取使用宿主既有凭据及受信路由；分页、观察完整性与错误可见。不支持的视图筛选明确说明限制，不用固定示例或全列表冒充真实视图。
- 会话、委派、作业与消费事实由真实宿主公开能力投影；历史只读。原型演示数据和模拟状态按钮不进入产品。
- 接续复用固定操作和后继，在安全维护边界转移并保留应收结果与具体决定。独立子 Task 的存在本身不阻止交接。
- 持续委托保存用户原话、授权来源、版本化模型计划、依据与 Block。模型仅提出候选，服务端重新校验身份、来源、负责人、依赖及执行资格，然后使用既有串行调度领取。
- 预览与启用是不同命令；模型失败显示失败，不退回固定安排。浏览、刷新、切来源不调用模型或启动工作。
- 默认沿用可用项目／宿主策略，执行资源与权限仍须明确授权。外部文本和模型输出不能扩大范围或权限。
- 验收先持久化，再收口、通知和可恢复外部关闭；未知回执先观察再重试。
- 已有未提交原型和研究保留。写任务各占持久 worktree，固定 base，逐阶段 commit＋push＋PR。安全面 fresh xhigh 评审一轮，必要整改由 CEO 逐条闭合。

## Testing Decisions

主要行为接缝是公开工作命令／查询与真实持久记录，断言身份、状态和副作用次数。确定性模型用于合同测试，最终自然语言计划及接续决定保留另有真实模型证据。

- 来源 URL、去重、Project view／切片恢复，真实读取及错误／缓存状态。
- 同 Issue 跨来源唯一，启动重放不多建会话，关联／评审／历史不抢协调权。
- 当前／子 Issue／实施／评审／作业及历史失败的真实统一状态。
- 接续准备到接任的入口时序、待收结果、重试复用、旧段失权和具体决定保留。
- 自然语言计划真实生成，预览零执行，服务端拒绝越界，Block／重规划／暂停／重启恢复及两项串行推进。
- 独立子项验收，本地完成与远端关闭失败恢复，已完成工作不重启。
- 真实既有 DSH 页面桌面／窄屏 agent-browser 截图与中文目的／步骤／记录报告，保留旧数据前后核对。构建通过不替代页面验收。

## Out of Scope

原型底部演示抽屉、伪造 Issue／token／作业／模型计划不进入产品。不执行 freeland 的真实业务任务，不做生产发布、跨主机协调或完整 GitHub UI 克隆。旧 v3 总规格其他能力保留原工单，不借本次验收一并关闭。

# 03 — 旧工作记录安全迁移与恢复接管

## Parent

主任务 [#120](https://github.com/a2d2-dev/dsh-plugin/issues/120)；本票 [#123](https://github.com/a2d2-dev/dsh-plugin/issues/123)。已确认并发布，执行标签 `ready-for-agent`。

## What to build

操作者在隔离的旧记录副本上预览迁移，看到稳定身份映射和待处理冲突；确认后在安全边界迁移一项旧工作，再从新控制面板查看原有会话历史和恢复同一次执行。迁移后旧入口通过同一新命令操作，不形成两套 writer/runner。

采用 expand → 兼容读取 → 单一新写入 → 协调权切换。它是升级端到端路径，不是一次横跨全仓、要求所有调用者同时改完的重写。

## Acceptance criteria

- [ ] 迁移预览列出旧地址到 Project/Task/Agent/Execution 与 Session 引用的映射，不启动会话或写源记录。
- [ ] 执行迁移前备份并记录格式版本、校验和与操作进度；中断重跑保持原映射和进行中的 operation IDs。
- [ ] 保留当前/历史会话、固定后继、接续记录、消息身份、暂存 inbox 和 watch 地址，不把“已创建未确认”恢复成新会话。
- [ ] 活动工作只在安全边界转移权威，旧协调者失权；同一存储域不会被新旧运行器同时驱动。不能只写一个旧 writer 看不懂的标志就声称已防双写。
- [ ] 旧 Issue 型命令只负责解析映射后进入统一新命令；新字段不能被旧格式 round-trip 丢弃。
- [ ] 外部身份碰撞、来源不明、非空会话配置/权限冲突或无法证明旧执行停止时，明确停止该项迁移并保留原记录。
- [ ] 历史完成记录保留来源和证据缺口，不伪造新验收证据，也不因证据格式不全自动重跑已完成工作。
- [ ] 新数据写入后的回退须关闭新 writer/runner 并执行兼容导出或恢复备份；旧程序不能直接覆盖新事实。
- [ ] 在真实旧格式 fixture 与隔离真实运行记录上验证：干运行、暂停/活动记录、迁移中断、重复迁移、接任后恢复、双写拒绝和回退限制，并从控制面板核对结果。

## Boundaries and evidence

本片不迁移任何现有生产目录，不迁移机器或容器 PID 命名空间。真实环境切换需要独立授权；新功能开发可在新隔离记录域继续，不必以历史 Issue 是否关闭作为阻塞条件。

# 07 — 本地验收完成、父通知与可恢复外部关闭

## Parent

主任务 [#120](https://github.com/a2d2-dev/dsh-plugin/issues/120)；本票 [#127](https://github.com/a2d2-dev/dsh-plugin/issues/127)。已确认并发布，执行标签 `ready-for-agent`。

## What to build

负责者依据标准、证据和必要子工作确认 Task 完成，系统可靠保存完成事实，再收口执行、通知父任务并按需关闭关联 Issue。用户可以同时看到“本地已完成”和“外部关闭失败/待同步”，只重试协同，不重跑工作。

## Acceptance criteria

- [ ] 提供记录证据、逐项标准结果、验收结论及完成的真实命令/模型工具，校验负责者、标准版本和必要子工作；仅有非空 summary、CLI 退出或 PR 检查通过不能完成 Task。
- [ ] 通过真实应用入口走通无Issue父Task→创建子Task→执行→记录证据/标准结果→完成子Task→父收到结果；不靠测试fixture私造父子关系或验收事实。
- [ ] 完成事实与 completion operation/outbox 意图可靠提交；父通知不能先于对应完成事实成立。
- [ ] 同一完成 command 重试幂等；执行收口、父通知、通知投递/消费和可选外部同步分别可查询并恢复。
- [ ] 无外部关联的本地任务正常完成、释放推进资格，必要时通知父 Task；没有 GitHub 关闭动作也成立。
- [ ] 已关联任务本地完成后，关闭 Issue 的待同步/失败/成功/结果未知准确显示；网络恢复不创建 Task、会话或新协调资格。
- [ ] 远端关闭已经成功但回执丢失时，先核对既有操作和对象；不能盲目重发不可安全重复的副作用。
- [ ] 停用协同保留完成事实和未完成操作；恢复后按版本调和。外部重开或负责人变更形成冲突，不自动倒退已完成事实。
- [ ] 完成详情显示最后处理会话及结束状态；相关运行委派安全收口。若验收本身要求远端合并/发布，必须取得相应证据而非把可选同步混为验收。
- [ ] 故障注入覆盖完成提交前后、父事件接受/消费、执行收口和外部回执；真实外部写验收只用授权的专用测试工作项。

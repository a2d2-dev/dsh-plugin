# 05 — 当前项目的真实视图与对应内容

## Parent

[A²D² v3 开发规格草案](../a2d2-control-panel-v3.md)。发布前草案；计划标签 `ready-for-agent`。

## What to build

研发选择一个 Project 后，在“项目”页看到该项目实际的视图标签、字段与对应内容，切换标签、搜索和分页得到一致结果；来源内容按 Issue、PR、草稿和受限条目区分，能回到相应详情。

复用已建立的来源读取与领域映射，不把原型的固定五个标签当作远端数据，也不要求 PR 评审执行能力先完成。

## Acceptance criteria

- [ ] 已关联外部 Project 时读取 view name/filter/fields 等能力和分页 items；未关联时使用明确的本地视图，不伪装成已读取远端。
- [ ] 视图标签由项目配置/来源驱动；切换后表格、字段、标签和计数对应当前视图。支持能力不足时明确降级，不静默改成全部内容。
- [ ] @me、分页、分组/排序、不可见字段与 Project 权限不足有明确行为；仓库可读不等于 Project 可读。
- [ ] 所有数据限定当前具体项目；切项目清除不适用的视图、筛选和详情；返回同项目列表保留来源位置。
- [ ] Issue 进入既有工作详情；PR 进入只读 PR 来源详情或已有 PR 详情，缺评审执行能力时明确提示；draft 明确为草稿，可只读查看或显式接入本地工作；不可见/缺失内容显示原因，不伪造 Task。
- [ ] 来源正文按不可信内容安全呈现，不执行嵌入脚本，不把来源文字升级为宿主权限或系统指令。
- [ ] 提供可供持续处理规则引用的来源视图身份、筛选快照和版本；单纯浏览视图不创建执行或扩展授权。
- [ ] 真实隔离 DSH 浏览器验证标签/内容/详情/返回；固定响应至少含 Issue、PR、draft、受限条目、分页和字段缺失。
- [ ] 使用目标 Project 的只读凭据对照实际视图结果，明确权限与支持范围；schema 可读不能代替实例验收。

## Blocked by

- 04 — GitHub Issue 来源、唯一接入与本地内容保留。

## Boundaries and evidence

不实现 PR 评审会话或 PR watch，不要求 09 先完成；不实现完整 GitHub 布局编辑器或全部筛选语言本地解释器。Project 内容中的 PR 只读分流与后续 PR 目录使用同一外部引用契约，避免两个详情身份。

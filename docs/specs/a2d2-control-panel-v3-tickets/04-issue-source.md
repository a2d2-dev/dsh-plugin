# 04 — GitHub Issue 来源、唯一接入与本地内容保留

## Parent

[A²D² v3 开发规格草案](../a2d2-control-panel-v3.md)。发布前草案；计划标签 `ready-for-agent`。

## What to build

研发为一个具体 Project 配置仓库来源，在控制面板看到分配给自己的 Issue，打开完整详情，并把需要处理的项接入已有本地工作模型或关联真实会话。来源离线时已接受的工作仍可读，不把失败列表展示成“没有任务”。

来源适配只在宿主读取凭据；先实现列表/详情、分页、来源观察和唯一映射，不在此片做远端修改。

## Acceptance criteria

- [ ] DSH 登录和 GitHub 来源权限分别校验；浏览器不持有 token、不提交任意宿主路径，项目查询范围由服务端解析。
- [ ] 读取 Issue 标题、正文、负责人、标签、远端状态和版本/观察信息；@me 指向所用来源凭据的真实用户并可辨认。
- [ ] 支持分页、空结果、权限不足、来源暂不可用和刷新；来源错误保留最后已知内容，不清空本地工作。
- [ ] 浏览列表不必创建 Task；显式接入/关联时保存内容快照、稳定 TaskId 和 ExternalBinding，再走统一应用命令。
- [ ] 同一个外部节点、规范化 URL、重复分页结果和已有子 Issue 都复用原映射；不同仓库同号 Issue 不串数据。
- [ ] 有本地记录时来源离线仍可查询、关联和继续已授权操作；只有远端 URL、从未取得内容的项明确受阻，不假装本地完整。
- [ ] 后关联和停用来源保持 Task/Agent/Execution/历史不变；停用后不继续导入或发布，映射和观察保留。
- [ ] 可从来源条目进入独立详情，再进入已有真实会话；未实现启动能力的部署明确提示所缺能力，不以虚构 Issue 运行。
- [ ] 固定响应测试覆盖重复、大小写/仓库重命名映射、分页中断、迟到观察、401/403和离线；真实目标凭据补只读 smoke，记录权限和分页证据。

## Blocked by

- 01 — DSH 单入口、本地项目与工作详情。

## Boundaries and evidence

不修改真实 Issue，不关闭或重开工作项，不把 PR watch 当来源目录。可与新领域启动切片并行开发；本片可独立演示“读取 → 接入 → 详情 → 进入已有会话”。

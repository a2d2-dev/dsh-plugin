# 02 — 单项工作启动、当前协调会话与执行资格

## Parent

[A²D² v3 开发规格草案](../a2d2-control-panel-v3.md)。发布前草案；计划标签 `ready-for-agent`。

## What to build

用户从一项本地工作详情点击“开始处理”，系统选择已配置的项目 Agent 与真实执行资源，原子申请协调资格，并通过 DSH 创建或复用真实会话。详情显示当前处理会话、运行/等待/失败状态和关联历史；重复点击不会另起一份工作。

复用既有根会话装配、运行器与事件收件箱，改为领域 Task/Execution 引用。保持“一 Task 一个有效协调者”和“一 Session 至多协调一个活动 TaskExecution”两个方向的约束。

## Acceptance criteria

- [ ] 单个用户意图可以编排指派、关联、申请资格和启动；每个事实与失败边界分别可查询，未启动不伪称运行中。
- [ ] 一次执行保存 ExecutionId、owner/epoch、负责 Project Agent、实际 host/cwd、可选检出、preset 与有效策略。
- [ ] 两个消费者启动同 Task、两个 Task 抢同 Session、重复点击及客户端重试均得到确定结果；不出现双 owner 或上下文串扰。
- [ ] 采用公开 SessionController/preset 和会话本地模型接口；成功后真实工具/资源/权限与选定环境一致，不修改宿主全局默认。
- [ ] 宿主创建成功但回执丢失时，重试核对固定执行与会话身份；不得因为未收到响应而创建第二条协调会话。
- [ ] 提供 TaskId 寻址的更新进展、等待/提问、暂停和恢复命令/模型工具，校验负责者与执行权限；等待时不空推，输入与结果接受、投递、消费和验收分别呈现，不能依赖旧 issue-bound resume。
- [ ] 有用途的处理/历史/工作者关联不能互相抢占协调身份；查看历史不恢复旧 Task 的执行权。普通宿主导航无只读能力时必须有真实的只读记录投影或受支持接口。
- [ ] 新 TaskRef 下的手动接续、固定后继与 prepare/write/create/take/deliver 恢复原语随本片落地；每个检查点失败后可由同一执行继续，不依赖自动 token 策略票才补齐 take/投递。
- [ ] 接任后原生新旧会话都能回同一工作详情，当前指针只按有效接任更新；会话内接续状态与控制面板一致。
- [ ] 旧已活动工作未完成安全迁移时保持原权威，新入口明确拒绝重复接管；不能移除旧运行器约束后直接开始。
- [ ] 合同测试组合真实本地记录、DSH loop/persistence/preset 与确定性模型适配，覆盖并发和创建回执窗口；浏览器证明“进入会话”指向真实当前实例。

## Boundaries and evidence

本片完成新领域任务的受控单项启动和运行观察，不声称活动旧记录已迁移，不开放多机锁或共享协调会话。自动 token 计量与触发策略、完整验收 outbox 和来源队列分别后续交付；必要的旧执行拒绝边界本片即须存在。

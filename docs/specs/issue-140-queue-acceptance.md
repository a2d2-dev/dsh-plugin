# #140 持续委托验收口径

## 工作身份与确认

原始工作仍为 [Issue #140](https://github.com/a2d2-dev/dsh-plugin/issues/140)，父 [#136](https://github.com/a2d2-dev/dsh-plugin/issues/136)，补足 [#128](https://github.com/a2d2-dev/dsh-plugin/issues/128) 的自然语言委托，复用既有持续处理槽位与 Task 协调身份。

2026-10-26，本 Task 协调会话向 LF 说明原 #140 与后续已确认 [#265](https://github.com/a2d2-dev/dsh-plugin/issues/265) 在入口、计划审批及并发上的冲突。LF 明确选择“沿用 #265，更新 #140 冲突标准”。该决定已保存为 Task 规格 v3，不把需求冲突冒充代码回归，也不把旧标准默认为通过。

| 原 #140 要求 | 本次明确采用的行为 |
| --- | --- |
| 来源表头右侧持续处理配置框 | PR 之后的常驻“持续委托”页签；菜单快捷入口切换到同一页签 |
| 每轮真实模型有序计划，预览后逐计划启用 | 一个 Project、一份队列设置；真实模型按自然语言筛选等待工作并给理由，排序采用保存设置；不增加逐轮计划审批对象 |
| 同时最多一项自动推进 | 使用保存的并发上限，默认 1；上限为 1 时验证两项串行，调低上限保留在途 |

历史计划接口与数据保留。其只读预览和服务端安全校验合同继续验证，但不恢复被替代的主界面。

## 当前九条验收标准

1. 保存自然语言筛选原话与补充、授权来源与执行资源、队列设置、模型筛选依据／理由及 Block；关闭浏览器及重启可恢复，既有计划与历史保留。
2. 真实模型结合来源 Issue 要求、父子／依赖及已有 Task／执行进展筛选等待工作并提供理由；失败明确报告，不使用固定示例或冒称理解任意条件。等待顺序采用保存设置。
3. 浏览／切换页面不启动模型或任务、不启用委托；用户显式保存范围并启用后按同一队列执行。服务端校验候选身份、来源范围、负责人、父子覆盖及依赖，越界或资格未满足的工作不自动推进。
4. Block／解除 Block 和自然语言筛选补充影响后续等待安排；Block 不强杀在途会话，暂停只停止后续接入，在途、历史与需人工项保留。
5. 同 Issue 跨来源复用 canonical Task；已有执行可受控接纳／继续，不简单跳过或再建 owner；一个 Task 不被多个来源规则同时推进。
6. 等待保留 owner 与会话并安全让槽，结果进入后按同一队列调度恢复；明确人停须显式恢复。
7. 按保存并发上限推进；发现、版本领取、启动未知回执、刷新与暂停竞争可恢复，不重复执行。
8. 独立页签和既有 Task／会话导航一致，无手动上移下移，草稿不被后台刷新覆盖。
9. 合同测试通过；最终真实模型筛选、并发为 1 的两项串行推进、Block／暂停／关闭浏览器与重启恢复有当前浏览器和持久记录证据。

## 边界与完成判断

不让模型直接控制目录、权限或任意网络，不新增平行调度器，不执行 freeland 实际业务任务。真实验收采用专用对象，不能将受控测试 adapter 当成真实模型证据。

Repo／view 组合和可靠完成在 [#141](https://github.com/a2d2-dev/dsh-plugin/issues/141) 最终整合验收；外部关闭成功不阻塞下一项。实现、测试通过或已部署均不单独等于整票接受，最终结果见对应验证报告。

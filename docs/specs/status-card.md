# Spec: 「下一步」卡片以「现状」开头，并附「当前位置」

状态: 已与 LF 收敛（2026-09）。词汇见 CONTEXT.md「边界卡」「现状」「当前位置」。前序: boundary-card.md。

## Problem Statement

用户经常切回一条会话时不知道它的状态：还在跑吗？是不是在等我审批？卡住了？出错了？还是早就停了？现在只能翻聊天流去猜。「它做到哪了」这类工作层面的状态，和「下一步」要回答的问题重合；而运行层面的状态是确定的事实，不需要问模型。

## Solution

指示球悬停露出两个平级入口，竖排在球上方，离球由近到远：**下一步 → 交接**（原「压缩」恢复为「交接」，与域词一致；hover 提示仍写「压缩当前上下文，开启新会话」）。

- **下一步**：卡片一打开，顶部立刻显示**现状**区块（不调模型，从会话快照读出运行状态、在跑的工具、待你处理的交互、上一轮结束时间、队列与上下文占用），填补咨询生成期间的空白；咨询返回后在其下方显示「当前位置：…」与候选芯片。咨询输出从候选数组改为 `{position, candidates}`。
- 迭代记录：最初「现状」是独立第三个按钮、卡底放「→ 下一步」；LF 试用后指出现状内容少、又总要接着点下一步，而下一步等待时是白屏——二者合并。
- **交接**：不变。

## Implementation Decisions

- **现状模型**（`src/client/status-model.ts`，纯函数）：`sessionStatus(snapshot, now)` 按优先级解析：已移除 > 未打开 > 在等你（pending 审批/问题，含工具名与理由）> 疑似卡住（运行中、无流式输出、且最新的轮次开始/工具调用距今 ≥ 10 分钟）> 运行中 > 出错了（`lastAgentError` / `promptError`）> 尚未开始（blank）> 空闲。只数 `placement: queued` 的排队消息。
- **数据来源**：`ClientConversationState` 扩展为会话快照的结构子集（`running` 之外全部可选），旧运行时退化为运行中/空闲两档，不报错。
- **刷新**：卡片打开时订阅快照，另加 15 秒时钟让经过时间和卡住判定保持准确；关闭即退订。
- **配色**：状态点颜色只在卡片内使用，不碰球体水位的 smart zone 告警色。
- **当前位置**：宿主 prompt 要求返回 `{"position": "...", "candidates": [...]}`；`parseConsultOutput` 要求 `position` 非空，缺失即整体按 malformed 拒绝（不出半成品）。客户端对缺失的 `position` 容忍，兼容旧宿主。
- 下一步卡与交接卡互斥；现状区块只在下一步卡打开期间订阅快照。
- **咨询稳健性**（真实故障修复）：`claude-opus-5-5` 路由默认思考，思考 token 与答案共用输出上限，768 上限下总输出约 650–690 已贴边，偶发 `max-tokens` → 上限提到 4096；模型常把 JSON 包进 ```json 围栏 → 解析器只剥离**包住整段**的单个围栏，围栏外有散文仍拒绝；失败时把原因（限流、超长、字段错误）附在错误消息里回显到卡片，不再一律「无法生成」。

## Testing Decisions

- `tests/client/status-model.spec.ts`：各档优先级、事实行文字、卡住阈值、流式不算卡住、排队计数、旧运行时退化。
- `tests/consult.spec.ts`：prompt 快照更新；输出解析覆盖裸数组、缺 position、空 position 等拒绝情形。
- `tests/client/consult-actions.spec.ts`：position 透传与非字符串拒绝。

## Out of Scope

- 在球体本身常驻显示运行状态（外圈/小点）。先看卡片的使用体感再议。
- 跨会话的状态总览（列出所有会话谁在等我）。
- 卡住阈值做成配置项。

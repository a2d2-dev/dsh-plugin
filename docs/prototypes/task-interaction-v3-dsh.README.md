# A²D² 控制面板 · DSH 内单入口原型

[打开独立 HTML](task-interaction-v3-dsh.prototype.html)。下载后直接用浏览器打开，无依赖、无需服务器。

本稿依据 LF 的最新反馈及三张参考图重做交互方向：**继续在 DSH 使用现有项目、会话和 skill，只增加一个 A²D² 控制面板入口。** 面板围绕 Issue、PR、项目展开，将工作进展与处理会话连接起来。

这份 HTML 中的 DSH 外壳也是示意，不是已经安装到真实 DSH 的插件。所有内容、消息、来源和接续均为内存模拟；刷新重置。没有真实模型、GitHub、磁盘执行或后台任务调用，没有重启、部署 18780/18781。

## 交互收敛

- 左侧保留项目与 DSH 会话；新增的产品入口只有“A²D² 控制面板”。
- 主导航只有 **Issue / PR / 项目**。领域身份、执行占用等留在行为约束里，不成为用户必须操作的栏目。
- Issue 列表同时显示外部 Open/Closed 与实际处理进展，可直接进入关联会话。
- 点击 Issue，在侧栏查看原始目标、7 项工作、子 Issue、待确认问题及最近进展；保持父工作背景。
- PR 连接对应 Issue 和评审会话。项目汇总已有工作的处理分布。
- “持续处理”沿用项目 skill；“自动接续”在处理会话附近设置。用户不用先创建一套 Agent 或手动推进业务阶段。
- 本地工作藏在“添加工作”的自然路径内：Issue 链接可留空，仍能进入 DSH 会话。

## 建议体验顺序

1. **第一屏**：查看 Issue 列表与左侧既有会话。点击 #112 镜像管理，展开整体进展；点击 #129 查看它属于哪项父工作，并进入关联会话。
2. **继续在会话里工作**：点击“进入处理会话”。会话顶部只增加关联 Issue、进展摘要与上下文接续入口；仍通过 DSH 对话补充要求。
3. **自动接续**：在 #112 侧栏回复清理策略；进入会话，将接续阈值设为 200K 或 300K。展开底部“原型演示”，模拟上下文增长。达到阈值后换到后继，摘要中保留刚才的具体决定，旧会话保留在历史中。
4. **持续处理**：回控制面板，点击列表下方“持续处理…”，选择项目范围并沿用现有开发 skill。已有处理会话会被复用；模拟收到验收通过后接下一项。暂停只停止接新工作。
5. **PR 和项目**：PR #211 展示检查失败，点击进入关联评审会话。项目视图查看处理分布，展开项目可看原始 Issue 以及来源设置。

底部演示按钮用于注入“新 Issue 到达、上下文增长、验收通过、来源不可用”等事件，明确与正常产品操作分开。模拟验收通过代表已取得必要验收结果，不表示真实产品可以省略验收。

## 浏览器验证

验证对象为独立 HTML。使用 `agent-browser` 独立会话 `a2d2-v3-dsh`，通过实际点击、填写表单、选择筛选、输入消息和注入模拟事件核验；桌面视口 1512×982，窄屏 390×844。未运行产品测试或操作真实工作项。

| 验证点 | 实际结果 |
| --- | --- |
| 单入口与对象导航 | 控制面板与原 DSH 会话来回切换；Issue / PR / 项目标签、项目筛选、标题或编号搜索可用 |
| Issue 展开 | #112 的 7 项工作、子 Issue #128/#129、待确认点和关联会话可见；保持父工作背景 |
| 子 Issue 去重 | 再次添加已有 #129 的链接，返回父工作 #112；工作数仍为 7，会话数仍为 5，不重复启动 |
| 接续阈值 | 300K 设置下，从 184K 增至 214K 仍使用原会话；设置 200K 后接续至第 3 段，旧会话归档、原工作仍 running |
| 接续内容 | 后继 checkpoint 保留目标、规格、7 项拆解、具体决定和近期输入；可见摘要包含“生产镜像保留 30 天；绝不按数量自动清理” |
| 持续处理去重 | 连续两次开启相同规则，均复用 #112 当前会话；会话数保持 6（此前已接续一次） |
| 完成后接下一项 | 来源不可用时模拟 #112 验收完成；本地 done、外部 Open、sync error；队列开始 #114，待确认/待评审项保留 |
| 暂停与补同步 | 暂停后 #114 会话仍 running；恢复来源后补同步关闭 #112，不创建新会话 |
| PR 会话关联 | #211 带入独立评审会话，反向关联 #112；重复打开复用同一评审会话，主处理会话仍是 s-02 |
| 项目来源断开 | 断开 rise 来源后，work-112 身份、running 状态和 s-02 会话不变；禁止注入新的远端 Issue，恢复来源后可以接收 |
| 当前对象寻址 | rise 队列仍处理 #112 时，进入 edge #87 会话；上下文增长仅影响 #87（18K→48K），验收事件只完成 #87；#112 保持 running |
| 本地工作 | 来源不可用时，链接留空创建本地工作，发送会话消息并模拟验收完成；remote 与 sync 均为空，无需 Issue |
| 窄屏 | 无页面级横向溢出；宽表在自身容器滚动；侧栏展开、搜索、回复表单和会话跳转可操作 |
| 隔离 | 浏览器错误列表为空；网络记录仅有 file: HTML 文档加载，没有 HTTP 请求 |

只读复核发现并修复了三个实际边界问题：已有子 Issue 重复接活、后继接续缺少具体决定、演示事件误作用于其他项目的队列工作。之后完成浏览器复验与独立复核。项目筛选、完成后同工作会话收口、表单按钮类型及动态进展文案也已修正。

## 原型边界

本稿验证入口、信息组织和跨对象跳转。DSH 会话 UI 是独立示意，真实宿主布局与公开 API 尚未接入；上下文增长、验收、轮询和模型回复没有真实执行。持续处理当前为串行示意，skill 选择只记录规则。子 Issue 只示范既有关联与回到父工作，不提供完整的远端新建/编辑能力。权限、实际模型窗口、调度公平性、跨运行实例互斥和持久恢复仍需正式实现契约。

本轮只新增第二稿与证据。上一份领域模型演示原型保持不变，提交 `b8bfe3f` 可用于对照；当前方向优先按 LF 本轮反馈评审。

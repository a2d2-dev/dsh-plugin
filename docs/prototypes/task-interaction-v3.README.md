# A²D² v3 交互原型

这是一份用于评审交互的独立、可点击 HTML，依据 [DDD v3 评审稿](../architecture/a2d2-ddd-review-v3.md) 制作。它回答的问题是：**完整的纯本地工作闭环，与可选 GitHub 协同，能否在同一个工作台清楚地共存？**

- [打开独立原型](task-interaction-v3.prototype.html)：下载后用现代浏览器直接打开，不需要安装、构建或启动服务器。
- 基线：`8ad5e620ff71078c1ca8ebe78aa15851dd988646`。
- 分支：`prototype/task-interaction-v3`。
- 所有数据仅在当前页面内存中。刷新恢复示例；“载入场景起点”会替换当前演示数据。
- 所有身份、目录、会话、执行、证据和 GitHub 引用均为模拟。没有网络请求、持久化、模型调用或真实任务操作，没有访问或重启 18780/18781 服务。

## 建议浏览顺序

1. **项目总览**：查看项目 Agent、任务、有效占用和可选协同入口。默认示例含一项 implement 任务和一项未指派任务。
2. **从零走纯本地流程**：左上“新建项目” → “项目 Agent / 添加 Agent”（选择 DSH native）→ “任务 / 创建任务”。填写目标、规格、逐行验收标准；不需要仓库或 Issue。
3. **指派并执行**：指派负责 Agent → 领取执行资格 → 配置资源并启动。启动时明确工作目录与权限；在“规格与工作”推进阶段，在“执行与接续”查看会话历史与执行占用。
4. **交接与等待**：交接主会话，观察业务阶段不变；可等待 LF 输入，或派发子执行后等待结果。在下方“演示场景”可注入宿主中断并恢复。
5. **本地验收完成**：推进至 review，逐项核验，保存证据与验收结论，再确认完成。独立子任务和运行中/失败待处理的委派会阻止完成。完成后释放执行资格，并记录父任务通知。
6. **可选 GitHub 协同**：启用项目协同，按任务关联 `example/research#42`；查看本地事实与远端最后观察。可解除任务关联或停用整个项目协同，再恢复原关联。
7. **复现边界场景**：展开页面下方“演示场景”，选择场景、点击“载入场景起点”，再逐步点击“下一步”。五个场景可反复载入：纯本地闭环、交接与恢复、关联与断开、完成后同步失败、冲突与执行权。

窄屏下主导航和任务标签可横向滚动，内容面板纵向排列。

## 原型里可以实际点击的内容

| 区域 | 操作与可见结果 |
| --- | --- |
| 项目 | 创建、切换本地项目，查看各自 Agent 与任务；项目身份独立于目录与仓库 |
| Agent | 新增名称、职责角色与 provider；CEO 为角色；原生与 Codex/Claude one-shot 能力明确区分 |
| 任务 | 创建完整目标/规格/验收、搜索筛选、指派、独立子任务与父通知 |
| 执行 | 领取资格、选择模拟目录/权限、显式启动、推进阶段、安全释放 |
| 接续 | 主会话换代、旧代失权、等待人类与消费回复、中断恢复同一会话 |
| 委派 | 原生 child 与 one-shot run 分别记录；等待多个结果，全部结算后继续；失败后核查副作用并新建尝试 |
| 验收 | 标准逐项核验、证据与结论、必要子工作门槛、本地完成与执行收口 |
| 协同 | 已有 Issue 关联、唯一映射、停用/解除/恢复、待同步、失败、结果未知先核对、冲突裁决 |
| 活动记录 | 区分领域事实、执行事件与外部观察，不从远端评论授予执行权 |

## 浏览器验证记录

**实验目的**：验证上述交互能够被实际点击驱动，且 DDD v3 的关键身份与状态边界清楚、相互独立。验证对象是本 HTML 原型，不是当前插件产品。

**方法**：使用 `agent-browser` 独立会话 `a2d2-v3-prototype` 直接打开本地 HTML。通过表单填写、下拉选择、按钮点击、复选框、导航与场景步骤操作；从页面读取结果状态。桌面视口 1440 × 1080，窄屏视口 390 × 844。截图为实际页面截图，部分为全页截图。关闭提示后采集核心场景截图。

本轮未新增产品测试、未运行全套产品测试，也未修改产品实现或正式 ADR。

## 本轮提议与后续定稿边界

本轮提出分步“指派 → 领取 → 启动”、任务详情中的三类事实展示、折叠演示区，以及外部指派需先安全释放资格再接纳的保守交互。它们服务于讨论，尚不构成正式实现契约。

原型将交接、输入消费、完成收口等动作同步模拟；真实事务、持久化、崩溃恢复、围栏与多 runtime 互斥尚未实现。目录与证据只保存演示引用，不做磁盘和权限核实；远端观察与网络错误由演示区注入。已有 Issue 关联支持规范化唯一映射与恢复原关联；未实现真实 Issue 创建/导入、任意外部字段合并或更换到另一 Issue 的映射迁移。正式状态机、冲突权限策略、附件与备份、共享协调会话、CLI 持久会话能力仍按 DDD v3 留待下一阶段。

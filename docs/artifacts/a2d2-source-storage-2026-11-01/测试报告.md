# 来源存储增长修复验收

## 目的

修复来源发现每页把稳定 observations/projectSnapshot 与累计 checkpoint 全量再次写入不可变 archive 的增长；保持原子提交、恢复、历史、幂等回执、权限和 owner/epoch 语义。提供停止全部读写者后使用的可达清理工具，不引入数据库，不操作实际生产数据。

## 基准结果

来源正文 20,315,567 B，初始 checkpoint 17,248,700 B。五次分页写入从188,126,035 B降至102,485 B，减少99.9455%；新增文件均为小 checkpoint 增量，未新增 source body；最终控制文件752 B。该轮耗时6161 ms降至3382 ms。CPU仍需比较累计 checkpoint 和必要的 reservation clone，本次优化主要减少实际写盘及不可达正文重复。

全量 vitest 另行运行中；最终结果交由本目录日志和后续交付记录补充。没有声称全量套件已通过。

## 边界

完整扫描完成时，观察时间等事实变化仍可能生成一个新的正文；命令回执及历史仍保留。离线清理只回收图中不可达 UUID 普通文件，不能按日期删除，也不设自动重启定时任务。GC 的 offline 声明要求全部读者和写者已停止；锁不能保护跨进程已持有的旧惰性快照。回退须使用全部可达目录备份或 `exportSnapshot()` 旧格式导出，不移除 storage 标记直接交给旧版本。
